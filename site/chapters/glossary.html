Glossary

Every term the course uses, defined in one to three sentences, with the Kestrel Labs example where it helps and links to the chapters that teach it.

A

A-MEM

An agentic memory system for LLM agents (Xu et al., 2025). Each memory is a note with keywords, tags and links to related notes, and adding a note can update the notes it links to, in the spirit of a Zettelkasten.

See: Chapter 30, Capstone 3

Access control list (ACL)

A list of the users or groups allowed to read a resource. In GraphRAG, ACLs have to follow the data into text units, entities, edges and every derived summary, because one community report can blend facts from documents with different permissions. Example: the board memo about the Deepcast supply crisis must not leak, through the DEEPCAST entity summary, into a community report every employee can read.

See: Chapter 29, Capstone 4

Adjacency list

A graph representation that maps each node to its neighbors, optionally with edge attributes. It uses memory proportional to nodes plus edges and makes "give me the neighbors of X", the core step of every traversal, fast.

See: Chapter 4, Chapter 13

Agent memory

Information an LLM agent keeps outside its context window so it survives across turns and sessions. Graph memory stores entities and dated facts, so the agent can update a fact (Priya Nair is now CTO) instead of appending a contradiction.

See: Chapter 30, Chapter 27, Capstone 3

Agentic GraphRAG

GraphRAG in which an LLM agent chooses which graph operations to call (search entities, expand neighbors, run a Cypher query, read a report), looks at the results and repeats until it has enough evidence. The alternative is a fixed retrieval pipeline.

See: Chapter 30, Chapter 18

Approximate nearest neighbor (ANN) search

Finding vectors that are probably the closest to a query vector without comparing against every vector. Index structures such as HNSW trade a little recall for large speedups on big collections.

See: Chapter 2, Chapter 13

B

Beam search

A search that keeps only the best B partial candidates at each step and expands only those. Think-on-Graph uses the LLM to score candidate relations and entities and keeps the top few reasoning paths at each depth.

See: Chapter 18

BFS (breadth-first search)

A traversal that visits nodes in order of hop distance from a start node, using a queue. It yields k-hop neighborhoods and unweighted shortest paths in time proportional to nodes plus edges. From Deepcast, BFS reaches Kestrel Labs, Marlow Dynamics and Project Tern at hop 1.

See: Chapter 4, Chapter 14

Bi-temporal

A data model that records two time axes for every fact: valid time (when it was true in the world) and transaction time, also called record time (when the system learned it or learned it had ended). minigraphrag stores them as valid_from/valid_to and recorded_at/invalidated_at; Graphiti as valid_at/invalid_at and created_at/expired_at. It can answer both "who was CTO in February 2026?" and "what did we believe on 1 March 2026?"

See: Chapter 10, Chapter 27, Capstone 3

Blocking

In entity resolution, a cheap first pass that groups candidate names (same normalized first token, shared embedding bucket, same type) so that expensive pairwise comparisons happen only inside a group. It avoids comparing all n² pairs.

See: Chapter 9

BM25

A sparse lexical ranking function. A document's score is the sum over query terms of IDF(q) · f(q,D)(k1+1) / (f(q,D) + k1(1 − b + b·|D|/avgdl)), with typical k1 between 1.2 and 2 and b = 0.75. It excels at rare exact names such as "Deepcast" that embeddings can blur.

See: Chapter 21

C

Centrality

A family of node-importance scores: degree, betweenness, closeness, eigenvector and PageRank. GraphRAG systems use them to decide which entities and edges get space when the context budget is tight.

See: Chapter 4, Chapter 14

Chain-of-thought (CoT)

Prompting a model to write intermediate reasoning steps before its answer. Graph-guided variants ground each step in nodes, edges or paths retrieved from a graph.

See: Chapter 23

Chunk

A contiguous span of a document used as the unit of embedding, extraction and citation. Microsoft GraphRAG calls chunks text units.

See: Chapter 2, Chapter 7

Claim

A dated, sourced statement extracted from text, with subject, object, claim type, status (TRUE, FALSE or SUSPECTED), start and end dates, a description and the source quote. Example: Marlow Dynamics ended Deepcast's outside supply contracts, status TRUE, 2025. Microsoft GraphRAG stores claims as covariates.

See: Chapter 10

Code graph

A graph of a software repository whose nodes are files, classes and functions and whose edges are relations such as defines, imports, calls and inherits. It lets an assistant answer call-chain and impact questions.

See: Chapter 32, Capstone 2

Community

A group of nodes more densely connected to each other than to the rest of the graph. In the Kestrel graph, {Marlow Dynamics, Deepcast} and {Brightwater Capital, Lena Park} are small communities.

See: Chapter 11

Community report

An LLM-written summary of one community, with a title, a summary, an impact rating with explanation, and a list of findings. Reports are the retrieval units of global search.

See: Chapter 12, Chapter 15

Connected component

A maximal set of nodes in which every pair is joined by some path. Many small components in an extracted graph often signal missed relationships or aliases that were never merged.

See: Chapter 4, Chapter 11

Context recall

The fraction of the gold supporting documents or facts that appear in the retrieved context. It measures retrieval separately from answer quality. In minigraphrag: context_recall(retrieved_doc_ids, supporting_docs).

See: Chapter 25

Context window

The maximum number of tokens a model can take in one call, counting prompt and output. Longer windows do not remove the need for retrieval: cost grows with tokens, and models use the middle of long inputs less reliably.

See: Chapter 1, Chapter 22

Cosine similarity

The cosine of the angle between two vectors: a·b / (|a| |b|), between −1 and 1. For unit-length vectors it equals the dot product, which is why vector stores often normalize embeddings.

See: Chapter 2

Covariate

Microsoft GraphRAG's name for extra records attached to entities, in practice claims. See Claim.

See: Chapter 10

Cross-encoder

A model that reads the query and a candidate passage together and outputs one relevance score. It is more accurate than comparing separate embeddings but must run once per pair, so it is used to rerank a short list.

See: Chapter 21

Cypher

A declarative query language for property graphs, used by Neo4j and other databases through openCypher. Patterns look like drawings: (p:Person)-[:CTO_OF]->(o:Organization).

See: Chapter 5, Chapter 20

D

Damping factor

In PageRank, the probability α that the random walker follows an outgoing edge instead of teleporting; 1 − α is the restart probability. The web default is 0.85 (minigraphrag's personalized_pagerank uses it too); HippoRAG's paper uses 0.5. A lower α restarts more often and keeps Personalized PageRank mass closer to the seeds.

See: Chapter 4, Chapter 17

Degree

The number of edges touching a node (in-degree and out-degree for directed graphs; weighted degree sums edge weights). A cheap importance signal; Kestrel Labs has the highest degree in the course graph.

See: Chapter 4, Chapter 14

Dense retrieval

Retrieval by similarity between learned embeddings of the query and the passages, as in Dense Passage Retrieval. It matches paraphrases well and misses rare exact tokens more often than BM25.

See: Chapter 2, Chapter 21

Description summarization

Merging the many per-chunk descriptions of one entity or relationship into a single coherent description with an LLM. Priya Nair might appear in five chunks with five partial descriptions that become one profile.

See: Chapter 9

DFS (depth-first search)

A traversal that follows one branch as deep as possible before backtracking, using a stack or recursion. It is used to enumerate paths and detect cycles; always cap the depth on real graphs.

See: Chapter 4

Directed graph

A graph whose edges have a direction, such as Marlow Dynamics → ACQUIRED → Deepcast. Many GraphRAG pipelines store directed relationships but traverse them as undirected for retrieval.

See: Chapter 4, Chapter 5

Directness

An evaluation criterion from the GraphRAG paper: how specifically and clearly the answer addresses the question. It was used as a control, since it tends to trade off against comprehensiveness and diversity.

See: Chapter 25

Diversity

An evaluation criterion from the GraphRAG paper: how varied an answer is in offering different perspectives and insights.

See: Chapter 25

Domain graph

A graph whose nodes are real-world entities and concepts (people, organizations, projects) and whose edges are semantic relationships. Contrast with a lexical graph, whose nodes are documents and chunks.

See: Chapter 6

DRIFT search

Dynamic Reasoning and Inference with Flexible Traversal, a Microsoft GraphRAG query mode. It first compares the question with the most relevant community reports to draft a broad answer and follow-up questions, then refines those with local search, returning a ranked hierarchy of answers.

See: Chapter 15

Dynamic community selection

A global search variant that walks the community hierarchy from the top, asks a cheaper LLM to rate each report's relevance, and only descends into children of relevant communities. Irrelevant reports never reach the map step, which cuts tokens.

See: Chapter 15

E

Edge weight

A number on an edge expressing strength, frequency or cost. In minigraphrag a merged edge's weight is the sum of the strength values of every extracted mention of that relationship, and modularity, PageRank and path pruning all read it.

See: Chapter 4, Chapter 9

Embedding

A dense vector representation of text (or a node, or an image) produced by a model so that similar meanings land close together. Chunks, entity descriptions and community reports are all embedded for search.

See: Chapter 2, Chapter 13

Empowerment

An evaluation criterion from the GraphRAG paper: how well an answer helps the reader understand the topic and make informed judgments.

See: Chapter 25

Entity

A distinct real-world thing, such as a person, organization, place, project, event or concept, represented as a node with a name, type, description and source ids. Kestrel Labs, Dr. Mira Okafor and Halden Reef are entities.

See: Chapter 5, Chapter 8

Entity linking

Mapping a mention in a query or document to a node in the graph. "the CEO" in a question about Kestrel should link to Dr. Mira Okafor. Seed selection in local search and HippoRAG is a form of entity linking.

See: Chapter 14, Chapter 17, Chapter 20

Entity resolution

Deciding which extracted names refer to the same real-world entity and merging them into one node. "Dr. Mira Okafor", "Mira Okafor" and "Okafor" should become one node; "Tidewater" and "TWI" should join "Tidewater Institute".

See: Chapter 9

Entity type

The category an extractor assigns to an entity from a fixed list, such as ORGANIZATION, PERSON, PROJECT, LOCATION, EVENT or LAW. Types constrain extraction, guide resolution and become node labels in a database.

See: Chapter 5, Chapter 8

Evidence panel

An interface pattern that shows the entities, paths and source passages behind an answer next to it, so users can check the answer instead of trusting it.

See: Chapter 21

Exact match (EM)

An answer metric that scores 1 if the normalized prediction equals the normalized gold answer and 0 otherwise. It is strict: "Priya Nair" matches, "Priya Nair, since March 2026" does not.

See: Chapter 25

Extraction

The indexing step in which an LLM reads a text unit and returns entities and relationships (and optionally claims) in a fixed output format.

See: Chapter 8

F

F1 (token F1)

The harmonic mean of token-level precision and recall between a predicted and a gold answer. It gives partial credit where exact match gives none.

See: Chapter 25

Faithfulness

How far every statement in an answer is supported by the retrieved context. An answer can be correct but unfaithful, if the model used its own memory instead of the evidence.

See: Chapter 23, Chapter 25

FastGraphRAG

An open-source GraphRAG framework by Circlemind that builds an entity graph with an LLM and uses PageRank-based exploration at query time, with the aim of lower cost than Microsoft GraphRAG.

See: Chapter 26, Chapter 28

Finding

One item in a community report: a short summary statement plus a longer explanation grounded in the community's data.

See: Chapter 12

Flow-based pruning

PathRAG's path filter. Resource starts at a source node and is split among neighbors and multiplied by a decay rate at each hop; nodes whose flow falls below a threshold are pruned early, and surviving paths are scored by their average flow.

See: Chapter 18

G

G-Retriever

A method for question answering over textual graphs (He et al., 2024). It retrieves a connected subgraph with a prize-collecting Steiner tree, encodes it with a GNN into a soft prompt, and also passes the subgraph as text to the LLM.

See: Chapter 19, Chapter 24

GFM-RAG

Graph Foundation Model for RAG (Luo et al., 2025). A query-dependent GNN, pre-trained on many graphs, scores entities in one pass for multi-hop retrieval and can be used on new datasets without retraining.

See: Chapter 19

Gleaning

A recall booster for extraction: after the first pass, tell the LLM that entities were missed and ask it to add them, then ask a yes/no question about whether any remain; repeat until it says no or max_gleanings rounds (1 by default in minigraphrag) are used.

See: Chapter 8

Global search

Microsoft GraphRAG's query mode for corpus-wide questions. It runs map-reduce over community reports at a chosen level: each batch of reports yields scored partial answers, low scores are dropped, and a final call combines the rest.

See: Chapter 15

GNN (graph neural network)

A neural network that computes node, edge or graph representations by repeatedly aggregating information from neighbors. In GraphRAG, GNNs score nodes for retrieval or encode subgraphs into vectors an LLM can read.

See: Chapter 19, Chapter 24

GNN-RAG

A method (Mavromatis and Karypis, 2024) in which a GNN reasons over a knowledge-graph subgraph to find candidate answers, then the shortest paths from question entities to those candidates are written as text for the LLM.

See: Chapter 19

Graph-constrained decoding

Restricting an LLM's token generation so it can only produce paths that exist in the graph. Graph-constrained Reasoning (GCR) builds a trie of valid knowledge-graph paths to enforce this, which rules out invented relations.

See: Chapter 23

Graph CoT

Graph Chain-of-Thought (Jin et al., 2024). The LLM alternates between reasoning, choosing a graph function to call (such as retrieving a node, reading a feature, checking neighbors) and reading the result, iterating until it can answer.

See: Chapter 23

Graph database

A database that stores nodes and edges natively and answers traversal queries efficiently, such as Neo4j, Memgraph or FalkorDB. Postgres with edge tables can play the same role at modest scale.

See: Chapter 13

Graph foundation model

A graph model pre-trained across many graphs so it transfers to new graphs with little or no retraining. GFM-RAG applies the idea to retrieval.

See: Chapter 19

Graph-R1

An agentic GraphRAG framework (Luo et al., 2025) that trains the model with end-to-end reinforcement learning to interact with a hypergraph knowledge environment over multiple turns.

See: Chapter 24

GraphGPT

A graph instruction tuning method (Tang et al., 2023) that aligns a graph encoder with an LLM through a projector and tunes the model on graph tasks in two stages.

See: Chapter 24

Graphiti

An open-source library from Zep for building temporally aware knowledge graphs for agents. It ingests episodes incrementally, keeps bi-temporal edges, and invalidates facts that newer information contradicts.

See: Chapter 27, Chapter 30, Capstone 3

GraphRAG

Broadly, any retrieval-augmented generation that uses graph structure to organize, retrieve or integrate knowledge. Narrowly, Microsoft's method and library: extract an entity graph, detect communities, write community reports, then answer with local, global or DRIFT search.

See: Chapter 0, Chapter 6, Chapter 28

Grounding

Tying generated statements to supplied evidence. Retrieval grounds answers; citations to source ids make the grounding checkable.

See: Chapter 1

H

Hallucination

Fluent output that is not supported by the input or by reality. Retrieval reduces hallucination only if the answer actually uses the evidence.

See: Chapter 1

Helpfulness score

In global search's map step, a 0 to 100 score the LLM attaches to each partial answer to say how much it helps answer the question. Low-scoring points are dropped and the rest are sorted before the reduce step.

See: Chapter 15

Hierarchical Leiden

Running Leiden recursively: any community larger than a maximum cluster size is partitioned again, producing levels from coarse to fine. Microsoft GraphRAG uses it to build its community hierarchy.

See: Chapter 11, Chapter 12

High-level keywords

In LightRAG, abstract theme words extracted from the question ("supply-chain risk") that are matched against relationships to gather broad context. Contrast with low-level keywords.

See: Chapter 16

HippoRAG

A retrieval method (Jiménez Gutiérrez et al., 2024) inspired by hippocampal memory. It builds a graph of OpenIE triples plus synonymy edges, seeds Personalized PageRank from the question's entities, and ranks passages by the mass of the nodes they contain. HippoRAG 2 adds passage nodes to the graph and links the query to triples rather than only to entities.

See: Chapter 17

HNSW

Hierarchical Navigable Small World, a graph-based approximate nearest neighbor index (Malkov and Yashunin). Searches start in a sparse top layer and descend to denser layers. Most vector databases offer it, and pgvector supports it alongside IVFFlat.

See: Chapter 13

HotpotQA

A multi-hop question answering dataset built on Wikipedia (Yang et al., 2018) whose questions require two supporting paragraphs, with annotated supporting facts. A standard benchmark for multi-hop retrieval.

See: Chapter 25

Hub node

A node with very high degree, such as Kestrel Labs or a generic entity like "the company". Expanding through hubs floods the context with loosely related facts, so retrievers cap, down-weight or skip them.

See: Chapter 4, Chapter 14, Chapter 17

Hybrid retrieval

Combining several retrievers, typically BM25, dense vectors and graph traversal, and fusing their rankings, often with reciprocal rank fusion and a reranker.

See: Chapter 21

Hyperedge

An edge that connects any number of nodes at once. "Brightwater Capital led Kestrel Labs' $40M Series B in 2025" is one n-ary fact that a hyperedge can hold without splitting it into pairs.

See: Chapter 6, Chapter 31

Hypergraph

A graph whose edges (hyperedges) can join more than two nodes. HyperGraphRAG and related methods use hypergraphs to keep n-ary facts intact.

See: Chapter 6, Chapter 31

I

Incremental indexing

Updating a graph index when documents are added, changed or removed without rebuilding everything: extract only new text units, upsert entities and edges, and recompute only the communities and reports that changed.

See: Chapter 27, Chapter 26

Instruction tuning

Fine-tuning a model on instruction and response pairs. Graph instruction tuning (GraphGPT, LLaGA, MuseGraph) teaches a model to read graph inputs and perform graph tasks.

See: Chapter 24

Invalidation

Marking a fact as no longer true when newer information contradicts it, rather than deleting it: close its valid-time interval and stamp when the system learned that (minigraphrag's valid_to and invalidated_at, Graphiti's invalid_at and expired_at). When Priya Nair became CTO in March 2026, Jonas Vehl's CTO_OF edge was invalidated, not erased.

See: Chapter 27, Capstone 3

K

k-hop neighborhood

All nodes reachable from a node within k edges, plus the edges among them. The 2-hop neighborhood of Project Tern includes Deepcast (1 hop, through REPLACES) and Marlow Dynamics (2 hops, through Priya Nair's FORMERLY_WORKED_AT edge).

See: Chapter 4, Chapter 14

Kestrel Labs corpus

The fictional running example of this course: an ocean-tech startup, its people, projects, investors, supplier and regulators. Every chapter builds and queries the same graph.

See: Chapter 0

KGQA

Knowledge graph question answering: answering natural-language questions from an existing knowledge graph, with benchmarks such as WebQSP, CWQ and MetaQA. Think-on-Graph, RoG and GNN-RAG were evaluated in this setting.

See: Chapter 18, Chapter 19

Knowledge graph

A graph of entities and typed relationships that encodes facts about a domain, usually with a schema or ontology. It can be stored as RDF triples or as a property graph.

See: Chapter 5

L

LazyGraphRAG

A Microsoft Research approach that skips LLM summarization at indexing time (using lightweight concept extraction and co-occurrence instead) and defers LLM work to query time, bringing indexing cost close to vector RAG.

See: Chapter 26

Leiden

A community detection algorithm (Traag, Waltman and van Eck, 2019) that fixes a flaw in Louvain: a refinement phase between local moving and aggregation guarantees that communities are well connected.

See: Chapter 11

Lexical graph

A graph of documents and their structure, with nodes for documents, sections and chunks and edges such as PART_OF and NEXT. Entities can be attached to it to form a hybrid graph.

See: Chapter 6, Chapter 7

LightRAG

A graph-based RAG system (Guo et al., 2024) that indexes entities and relationships with key-value descriptions and retrieves in two levels: low-level keywords match entities, high-level keywords match relationships. It supports incremental updates by merging new subgraphs.

See: Chapter 16

Linearization

Turning a graph or subgraph into text an LLM can read: triples, markdown tables, adjacency lists, JSON or natural-language sentences. The format and ordering both affect answer quality.

See: Chapter 22

LLaGA

Large Language and Graph Assistant (Chen et al., 2024). It turns each node's neighborhood into a structure-aware sequence and maps it into the LLM's token embedding space with a trained projector.

See: Chapter 24

LlamaIndex PropertyGraphIndex

LlamaIndex's index type for building and querying labeled property graphs, with pluggable extractors and retrievers and support for graph stores such as Neo4j.

See: Chapter 28

LLM-as-judge

Using an LLM to grade answers against criteria or against each other. Useful when there is no single gold answer, but sensitive to position, length and self-preference biases, so randomize order and check agreement.

See: Chapter 25

Local search

Microsoft GraphRAG's query mode for questions about specific entities. It links the question to seed entities by embedding, gathers their relationships, claims, community reports and source text units, and fills a token budget with ranked tables.

See: Chapter 14

Lost in the middle

The finding (Liu et al., 2023) that language models use information at the start and end of a long context more reliably than information in the middle. It is why context builders put the strongest evidence at the edges.

See: Chapter 1, Chapter 22

Louvain

A greedy modularity-maximization algorithm (Blondel et al., 2008). It repeats two phases: move single nodes to the neighboring community with the best modularity gain, then collapse communities into super-nodes.

See: Chapter 11

Low-level keywords

In LightRAG, specific entity words extracted from the question ("Deepcast", "Project Tern") that are matched against entity embeddings to retrieve precise facts.

See: Chapter 16

M

Map-reduce

A two-step pattern: apply the same operation to many pieces independently (map), then combine the partial results (reduce). Global search maps the question over batches of community reports and reduces the partial answers.

See: Chapter 15

MATCH

The Cypher clause that describes a graph pattern to find, such as MATCH (p:Person)-[:CO_LEADS]->(:Project {name: 'Project Tern'}) RETURN p.name.

See: Chapter 5, Chapter 20

Message passing

The core operation of most GNNs: each node builds a message from its neighbors' current representations, aggregates the messages (sum, mean, attention) and updates its own representation. k rounds give each node a k-hop receptive field.

See: Chapter 19

Metapath

A sequence of node and edge types that defines a kind of connection, such as Person → FORMERLY_WORKED_AT → Organization → ACQUIRED → Organization. Following metapaths retrieves only meaningful routes instead of every path.

See: Chapter 21

minigraphrag

The course's small Python reference implementation of GraphRAG: chunking, extraction, resolution, communities, reports, indexing, several search methods and evaluation, runnable offline.

See: Chapter 0, Capstone 1

MockLLM

minigraphrag's deterministic offline LLM. It recognizes each prompt by a marker phrase and answers with heuristics: gazetteer-based extraction, extractive answers built from the context sentences. Pipelines and tests run without an API key or network, but its answers show what retrieval supplied, not how well a model would reason.

See: Chapter 0

Modularity

A score for a partition: Q = (1/2m) Σij [Aij − γ kikj/2m] δ(ci, cj), where m is total edge weight, ki is a node's degree and γ is the resolution. It compares edges inside communities with what a random graph with the same degrees would give.

See: Chapter 4, Chapter 11

Multi-hop question

A question whose answer requires combining facts from several places. "Why did Kestrel Labs start Project Tern?" needs acquisition, supply and project facts from different chunks.

See: Chapter 3

MultiHop-RAG

A benchmark (Tang and Yang, 2024) of multi-hop queries over a news corpus, with inference, comparison, temporal and null query types, for testing retrieval and answering.

See: Chapter 25

Multimodal knowledge graph

A knowledge graph whose nodes or attributes include images, tables, audio or video segments alongside text entities.

See: Chapter 31

N

Neighborhood expansion

Retrieving the entities that match a query, then adding their k-hop neighbors and the connecting edges as context. It is the first of the seven Graph RAG designs and the core of local search.

See: Chapter 14, Chapter 21

Neo4j

A widely used property graph database queried with Cypher. It offers vector indexes and an official GraphRAG Python package.

See: Chapter 13, Chapter 20, Chapter 28

NetworkX

A pure-Python library for building and analyzing graphs. It is ideal for learning and for graphs up to a few hundred thousand edges; minigraphrag uses it throughout.

See: Chapter 4, Chapter 13

Node specificity

HippoRAG's weight for a node, the inverse of the number of passages it appears in. Rare entities get stronger seeds in Personalized PageRank, like IDF for graph nodes.

See: Chapter 17

Normalization (entity names)

Rewriting names into a canonical comparison form: case folding, trimming punctuation and titles ("Dr."), collapsing whitespace. It is the cheapest step of entity resolution.

See: Chapter 9

O

Observability

Being able to see what a running system did and why: traces of each retrieval step, prompts, token counts, latency, cost and the ids of evidence used for each answer.

See: Chapter 29

Ontology

A formal specification of the types of things in a domain, their properties and the relations allowed between them, often with inheritance and constraints (for example in OWL). Stronger than a simple schema.

See: Chapter 5

OpenIE

Open information extraction: pulling (subject, relation, object) triples from text without a fixed schema of relation types. HippoRAG builds its graph from LLM-based OpenIE.

See: Chapter 17

Overlap

The number of tokens (or words) consecutive chunks share. Overlap keeps a sentence or relationship that straddles a boundary intact in at least one chunk, at the cost of duplicate extraction work.

See: Chapter 2, Chapter 7

P

PageRank

A node-importance score: the stationary probability that a random walker is at a node, where at each step it follows a random edge with probability α or jumps to a random node otherwise. Computed by power iteration: r = (1−α)/N + α · M r.

See: Chapter 4, Chapter 17

Pairwise evaluation

Showing a judge two answers to the same question and asking which is better on a criterion. Relative judgments are more stable than absolute scores; swap positions to cancel order bias.

See: Chapter 25

Path retrieval

Retrieving chains of edges that connect query entities, rather than isolated nodes or chunks, so the model sees how facts link. Marlow Dynamics → ACQUIRED → Deepcast → SUPPLIED → Kestrel Labs explains Project Tern.

See: Chapter 18

PathRAG

A graph RAG method (Chen et al., 2025) that retrieves relational paths between retrieved nodes, prunes them with flow-based pruning, and places paths in the prompt ordered by reliability.

See: Chapter 18

PCST (prize-collecting Steiner tree)

An optimization that picks a connected subgraph maximizing the prizes of included nodes (relevance to the query) minus the costs of included edges. G-Retriever uses it to extract a compact, connected subgraph.

See: Chapter 19

Personalized PageRank (PPR)

PageRank in which the walker restarts, with probability 1 − α, at a chosen seed distribution instead of a uniform one. Mass concentrates on nodes close to and well connected with the seeds, which makes it a multi-hop relevance score.

See: Chapter 17

pgvector

A PostgreSQL extension that adds a vector column type, distance operators and HNSW and IVFFlat indexes, so embeddings can live next to relational and edge tables.

See: Chapter 13

Plan-on-Graph (PoG)

A knowledge-graph reasoning method (Chen et al., 2024) that decomposes a question into sub-objectives, explores the graph adaptively, and uses memory and reflection to correct wrong exploration paths.

See: Chapter 18

Prompt caching

Reusing the provider-side computation for an identical prompt prefix across calls, which lowers cost and latency. Put static instructions and examples first and variable text last to benefit.

See: Chapter 26

Prompt injection

Text that tries to override a model's instructions. In GraphRAG it can arrive through indexed documents, be copied into entity descriptions and community reports, and reach many future queries.

See: Chapter 29

Property graph

A graph model in which nodes and edges have labels or types and arbitrary key-value properties, such as a CTO_OF edge with since and until properties. Used by Neo4j and most GraphRAG tools.

See: Chapter 5

Provenance

The record of where a fact came from: document, text unit, character span, extraction run and time. It enables citations, debugging bad edges, deletions and access control.

See: Chapter 7, Chapter 21, Chapter 29

Q

Query-focused summarization (QFS)

Summarizing a document collection with respect to a question. The GraphRAG paper frames global sensemaking questions such as "What are the main themes?" as QFS.

See: Chapter 12, Chapter 15

Query routing

Choosing a retrieval strategy per question, for example local search for entity questions, global search for themes, Text2Cypher for aggregates.

See: Chapter 21, Chapter 29

R

RAG (retrieval-augmented generation)

Answering with an LLM after retrieving relevant external information and placing it in the prompt. It adds fresh or private knowledge without retraining and makes answers citable.

See: Chapter 1, Chapter 2

RAPTOR

Recursive Abstractive Processing for Tree-Organized Retrieval (Sarthi et al., 2024). It clusters chunk embeddings, summarizes each cluster, and repeats on the summaries to build a tree; retrieval can search all levels at once.

See: Chapter 6, Chapter 12

Rating

The impact or importance score (0 to 10 in Microsoft GraphRAG) an LLM assigns to a community report, with a short explanation. It can be used to rank reports.

See: Chapter 12

RDF

Resource Description Framework, the W3C model that represents knowledge as subject-predicate-object triples with IRIs as identifiers, queried with SPARQL.

See: Chapter 5

Recall@k

The fraction of relevant items that appear in the top k retrieved results.

See: Chapter 25

Reciprocal rank fusion (RRF)

A way to merge ranked lists without comparable scores: each item gets Σ 1/(k + rank) over the lists it appears in, commonly with k = 60 (Cormack et al., 2009).

See: Chapter 21

Record delimiter

The separator between records in delimited extraction output; minigraphrag and Microsoft GraphRAG's default prompts use ##, and the output ends with <|COMPLETE|>.

See: Chapter 8

Reification

Turning a relationship into a node so that it can carry its own properties and links. The Series B becomes a FundingRound node connected to Brightwater Capital, Kestrel Labs, an amount and a date.

See: Chapter 5, Chapter 31

Relationship

A typed or described connection between two entities. In minigraphrag each extracted Relationship has a source, target, description, strength and one source_id; merging turns all mentions into one edge with a summed weight and a source_ids list. Example: Deepcast SUPPLIED Kestrel Labs from 2022 to 2025.

See: Chapter 5, Chapter 8

Relationship strength

The 1 to 10 score the extractor assigns to how strong a relationship is (Relationship.strength). Merging sums the strengths of all mentions into the edge's weight.

See: Chapter 8, Chapter 9

Reranker

A second-stage model that reorders a short candidate list by relevance, usually a cross-encoder or an LLM.

See: Chapter 21

Resolution parameter

The γ in modularity. Values above 1 favor more, smaller communities; values below 1 favor fewer, larger ones.

See: Chapter 11

RoG (Reasoning on Graphs)

A method (Luo et al., 2024) that fine-tunes an LLM to generate relation paths as plans, retrieves the matching paths from the knowledge graph, and reasons over them to answer faithfully.

See: Chapter 23, Chapter 24

S

Schema

The declared node labels, relationship types and properties a graph uses. A schema given to the extractor keeps types consistent; given to Text2Cypher it keeps queries valid.

See: Chapter 5, Chapter 20

Seed entity

A node chosen as the starting point of retrieval because it matches the question, by embedding similarity or name match. Local search expands from seeds; PPR teleports to them.

See: Chapter 14, Chapter 17

Soft prompt

Learned continuous vectors inserted into the LLM's input embeddings in place of or alongside text tokens. G-Retriever and GraphToken pass a graph to the LLM this way.

See: Chapter 19, Chapter 24

source_ids

The list of text unit ids a merged entity or relationship was extracted from. Each extracted mention carries a single source_id; merging collects them into source_ids. It powers citations, lets you delete a document's facts cleanly, and tells incremental indexing what to recompute.

See: Chapter 7, Chapter 9, Chapter 27

SPARQL

The W3C query language for RDF data, based on triple patterns such as ?person ex:ctoOf ex:KestrelLabs.

See: Chapter 5

Sparse retrieval

Retrieval with high-dimensional, mostly-zero term vectors, such as BM25 or learned sparse models. Strong on exact terms, names and codes.

See: Chapter 21

Subgraph assembly

Building a small, connected subgraph that covers all the query's entities (for example via shortest paths or PCST) and giving it to the model as one coherent piece of evidence.

See: Chapter 19, Chapter 21

Summary leakage

When a generated summary (entity description or community report) exposes facts from sources the reader is not allowed to see, because it was built from mixed-permission data.

See: Chapter 29

Synonymy edge

An edge HippoRAG adds between nodes whose names have very similar embeddings ("Tidewater" and "Tidewater Institute"), letting PPR flow across aliases that resolution missed.

See: Chapter 17

T

Teleport

In PageRank, the random jump to a node chosen from the teleport distribution, taken with probability 1 − α. In Personalized PageRank the jump lands on seed nodes.

See: Chapter 17

Temporal window

Restricting retrieval to facts valid in a time range. "Who supplied Kestrel's sonar in 2024?" should only see edges valid in 2024, which returns Deepcast.

See: Chapter 21, Chapter 27

Text unit

Microsoft GraphRAG's name for a chunk: the span of text sent to extraction, with a stable id that every derived entity, relationship and claim cites.

See: Chapter 7

Text2Cypher

Generating a Cypher query from a natural-language question, given the graph schema, then validating, running and possibly repairing it. It answers precise and aggregate questions ("how many projects does Priya Nair lead?").

See: Chapter 20

Think-on-Graph (ToG)

A method (Sun et al., 2023) in which the LLM acts as an agent on a knowledge graph, running a beam search that repeatedly explores and prunes relations and entities, until it judges that the collected paths answer the question. ToG 2.0 interleaves graph and text retrieval.

See: Chapter 18

Token budget

The number of tokens allotted to retrieved context, often split across sections (entities, relationships, reports, source text). Builders rank items and add them until the budget is full.

See: Chapter 14, Chapter 22

Tool calling

Letting an LLM request calls to declared functions with structured arguments, such as expand_neighbors(entity, hops), and continue after reading the results. It is how agentic GraphRAG accesses the graph.

See: Chapter 30

Transaction time

In a bi-temporal model, when the system recorded a fact or recorded that it had ended, regardless of when it was true in the world. minigraphrag and Capstone 3 call it record time (recorded_at, invalidated_at).

See: Chapter 10, Chapter 27

Triple

A (subject, predicate, object) statement, the atomic unit of RDF and a common linearization format: (Marlow Dynamics, ACQUIRED, Deepcast).

See: Chapter 5, Chapter 22

Tuple delimiter

The separator between fields of one extracted record. minigraphrag and Microsoft GraphRAG's default prompts use <|>, as in ("entity"<|>DEEPCAST<|>ORGANIZATION<|>Sonar supplier).

See: Chapter 8

U

Union-find

A disjoint-set data structure with near-constant-time find and union operations. Entity resolution uses it to merge chains of matches: if A matches B and B matches C, all three end in one cluster.

See: Chapter 9

Upsert

Insert a record if it does not exist, otherwise update it. Incremental graph updates upsert entities and edges by canonical key and append new source_ids.

See: Chapter 27

V

Valid time

In a bi-temporal model, the period during which a fact was true in the world. Jonas Vehl's CTO_OF edge is valid from 2021 to March 2026.

See: Chapter 10, Chapter 27

Variable-length path

A Cypher pattern that matches paths of a range of lengths, such as (a)-[*1..3]-(b). Always bound the upper length, since unbounded patterns can explode.

See: Chapter 5, Chapter 20

Vector store

A system that stores embeddings with ids and metadata and answers nearest-neighbor queries, from an in-memory matrix to pgvector or a dedicated database.

See: Chapter 2, Chapter 13

Z

Zep

A memory service for AI agents whose core is Graphiti, a temporal knowledge graph that tracks episodes, entities and bi-temporal facts (Rasmussen et al., 2025).
