Capstone 2: a codebase assistant on a code graph

Code is the one corpus where the graph comes for free: imports, calls and class hierarchies are already there, precisely, in the syntax tree. In this capstone you parse a real Python repository into a symbol graph and build an assistant that answers “what calls this?”, “what breaks if I change it?” and “how is this package organized?” with evidence it can cite by file and line.

You will be able to

  • Parse a Python package with ast into modules, classes, functions, methods and CALLS, IMPORTS, CONTAINS and INHERITS edges, with docstrings as text
  • Answer structural questions with symbol lookup, call-chain paths and reverse-BFS impact analysis
  • Summarize architecture with community detection and minigraphrag's report generator
  • Load the graph into Neo4j and answer counting and listing questions with validated Text2Cypher
  • Combine BM25 over identifiers, embeddings over docstrings and call-graph expansion with reciprocal rank fusion
  • Evaluate the assistant on a golden set for a real repository and explain where static analysis misses edges

Overview and architecture

Ask a vector RAG system over a repository “what breaks if I change fit_to_budget?” and it returns chunks that mention budgets. The answer you need is a set of functions reachable backwards through the call graph, most of which never mention budgets at all. That is a graph traversal, and Chapter 32 showed the two-pass parser that recovers the graph. This capstone turns it into an assistant with the same shape as the GraphRAG systems in the rest of the course: an index (the symbol graph plus text units), several retrievers, a router, cited answers and an evaluation harness.

Which repository?

Use two. Develop against minigraphrag itself (code/minigraphrag): you know it well, so you can write gold answers quickly and notice wrong ones. Then evaluate on a small, well-known open-source package you did not write. requests is a good choice: about 18 modules, real class hierarchies, and a famous indirection (a session picks a transport adapter at run time) that exposes the limits of static call graphs. click, attrs or httpx work too. Pin the version you parse; call graphs change between releases.

Requirements

Functional

  • Parse any pure-Python package directory into a networkx.MultiDiGraph with node kinds module, class, function and method, and edge keys CONTAINS, CALLS, IMPORTS and INHERITS. Each node keeps its path, line range, signature, docstring and source.
  • Tools: lookup(name), call_chains(src, dst, k), impact(symbol, max_depth), architecture reports, Text2Cypher over Neo4j with validation, and hybrid search.
  • An assistant that classifies each question, runs the right tool, falls back to hybrid search when a tool returns nothing, and answers with file:line citations.

Evidence

  • A golden set of at least 30 questions about your chosen repository, covering callers, impact, chains, locate-by-description and structural counts, with hand-checked gold symbol sets.
  • Per-type precision and recall of retrieved symbols, validity of returned call chains, and routing accuracy.
  • A written list of the false negatives with their cause (dynamic dispatch, local variables, callbacks, decorators).

Constraints

  • Parsing and every structural tool run without an LLM. The LLM writes Cypher and final answers only.
  • Generated Cypher is validated with minigraphrag's validate_cypher before it reaches the database, and runs in a read transaction.
  • Never execute the code you analyze.

Milestone C2.1 Parse the repository into a symbol graph

Build the index. Resolution is the hard part: count_tokens(text) in chunking.py must become an edge to minigraphrag.tokens.count_tokens, which requires knowing that chunking.py did from .tokens import count_tokens.

  1. Pass one: walk every .py file, compute its dotted module name, declare modules, classes, functions and methods (qualified ids such as minigraphrag.indexer.Index.report), and record each module's import table, resolving relative imports.
  2. Pass two: add IMPORTS edges between modules, INHERITS edges for base classes, and CALLS edges by resolving each call's dotted name through: self.method within a class, the import table, then the current module.
  3. Calling a class is a call to its constructor: resolve to the class node (or __init__).
  4. Keep the source text of every symbol; docstrings plus signatures are the text units for search.

"""Parse a Python repository into a symbol graph with Python's own ast module."""
from __future__ import annotations

import ast
from dataclasses import dataclass, field
from pathlib import Path

import networkx as nx


@dataclass
class Symbol:
    id: str              # qualified name, e.g. minigraphrag.chunking.chunk_fixed
    kind: str            # module | class | function | method
    path: str
    lineno: int
    end_lineno: int
    signature: str = ""
    docstring: str = ""
    source: str = ""


@dataclass
class ModuleInfo:
    name: str
    tree: ast.Module
    imports: dict[str, str] = field(default_factory=dict)   # local alias -> qualified target


def module_name(root: Path, path: Path) -> str:
    rel = path.relative_to(root.parent).with_suffix("")
    parts = list(rel.parts)
    return ".".join(parts[:-1] if parts[-1] == "__init__" else parts)


def _resolve_relative(current: str, is_package: bool, level: int, target: str | None) -> str:
    base = current.split(".")
    base = base if is_package else base[:-1]
    if level > 1:
        base = base[: len(base) - (level - 1)]
    return ".".join(base + ([target] if target else []))


def _signature(node: ast.FunctionDef | ast.AsyncFunctionDef) -> str:
    return f"def {node.name}({ast.unparse(node.args)})" + (f" -> {ast.unparse(node.returns)}" if node.returns else "")


def parse_repo(package_dir: str | Path) -> nx.MultiDiGraph:
    root = Path(package_dir).resolve()
    G = nx.MultiDiGraph()
    modules: dict[str, ModuleInfo] = {}

    # Pass 1: declare every module, class, function and method, and record imports.
    for path in sorted(root.rglob("*.py")):
        name = module_name(root, path)
        text = path.read_text(encoding="utf-8")
        tree = ast.parse(text, filename=str(path))
        info = modules[name] = ModuleInfo(name, tree)
        G.add_node(name, **vars(Symbol(name, "module", str(path), 1, len(text.splitlines()),
                                       docstring=ast.get_docstring(tree) or "")))
        for node in ast.walk(tree):
            if isinstance(node, ast.Import):
                for a in node.names:
                    info.imports[a.asname or a.name.split(".")[0]] = a.name if a.asname else a.name.split(".")[0]
            elif isinstance(node, ast.ImportFrom):
                src = _resolve_relative(name, path.name == "__init__.py", node.level, node.module) if node.level else node.module
                for a in node.names:
                    info.imports[a.asname or a.name] = f"{src}.{a.name}"
        for node in tree.body:
            _declare(G, node, name, "module", str(path), text)

    # Pass 2: IMPORTS edges, then CALLS and INHERITS edges resolved through each module's names.
    for name, info in modules.items():
        for target in set(info.imports.values()):
            mod = target if target in modules else target.rsplit(".", 1)[0]
            if mod in modules and mod != name:
                G.add_edge(name, mod, key="IMPORTS", type="IMPORTS")
        for node in ast.walk(info.tree):
            if isinstance(node, ast.ClassDef):
                cls = f"{name}.{node.name}"
                for base in node.bases:
                    target = _resolve(G, info, ast.unparse(base), None)
                    if target:
                        G.add_edge(cls, target, key="INHERITS", type="INHERITS")
                for item in node.body:
                    if isinstance(item, (ast.FunctionDef, ast.AsyncFunctionDef)):
                        _add_calls(G, info, f"{cls}.{item.name}", item, cls)
            elif isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)) and f"{name}.{node.name}" in G:
                if G.nodes[f"{name}.{node.name}"]["kind"] == "function":
                    _add_calls(G, info, f"{name}.{node.name}", node, None)
    return G


def _declare(G, node, parent: str, parent_kind: str, path: str, text: str) -> None:
    lines = text.splitlines()
    if isinstance(node, ast.ClassDef):
        qid, kind, sig = f"{parent}.{node.name}", "class", f"class {node.name}"
    elif isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
        qid, kind, sig = f"{parent}.{node.name}", "method" if parent_kind == "class" else "function", _signature(node)
    else:
        return
    source = "\n".join(lines[node.lineno - 1: node.end_lineno])
    G.add_node(qid, **vars(Symbol(qid, kind, path, node.lineno, node.end_lineno, sig,
                                  ast.get_docstring(node) or "", source)))
    G.add_edge(parent, qid, key="CONTAINS", type="CONTAINS")
    if kind == "class":
        for item in node.body:
            _declare(G, item, qid, "class", path, text)


def _resolve(G, info: ModuleInfo, dotted: str, cls: str | None) -> str | None:
    """Map a name used in module `info` to a declared symbol id, or None if it is external."""
    head, _, rest = dotted.partition(".")
    candidates = []
    if head == "self" and cls and rest:
        candidates.append(f"{cls}.{rest}")
    if head in info.imports:
        candidates.append(info.imports[head] + (f".{rest}" if rest else ""))
    candidates.append(f"{info.name}.{dotted}")
    for c in candidates:
        if c in G:
            return c
        if c.endswith("__init__") is False and f"{c}.__init__" in G:
            return f"{c}.__init__"   # calling a class runs its constructor
    return None


def _add_calls(G, info: ModuleInfo, caller: str, fn, cls: str | None) -> None:
    for node in ast.walk(fn):
        if isinstance(node, ast.Call):
            try:
                dotted = ast.unparse(node.func)
            except Exception:
                continue
            target = _resolve(G, info, dotted, cls)
            if target and target != caller:
                G.add_edge(caller, target, key="CALLS", type="CALLS", lineno=node.lineno)

Counts at the time of writing: minigraphrag parses to about 220 nodes and 510 edges; requests 2.32.3 to 292 nodes (18 modules, 44 classes, 72 functions, 158 methods) and 568 edges (274 CONTAINS, 207 CALLS, 55 IMPORTS, 32 INHERITS). Your numbers will differ with versions.

Two simplifications to know about. Nested functions are not declared, so calls inside them are attributed to the enclosing function (which is what you want for impact analysis). And ast.walk over a method includes calls in nested lambdas and comprehensions, also attributed to the method.

Milestone C2.2 Lookup, call chains and impact

Three deterministic tools cover most developer questions about structure.

  1. lookup(name): exact qualified id, then suffix match (report matches Index.report), then fuzzy match on short names for typos.
  2. edge_view(G, *types): a simple DiGraph with only the requested edge types, so traversals do not wander through CONTAINS or IMPORTS.
  3. call_chains(src, dst, k): the k shortest simple paths over CALLS with nx.shortest_simple_paths.
  4. impact(symbol, max_depth): BFS over reversed CALLS and INHERITS edges, grouped by distance.

"""Structural retrieval over the code graph: symbol lookup, call chains, impact analysis."""
from __future__ import annotations

from collections import deque
from difflib import get_close_matches
from itertools import islice

import networkx as nx


def edge_view(G: nx.MultiDiGraph, *types: str) -> nx.DiGraph:
    """A simple DiGraph holding only edges of the given types (CALLS, IMPORTS...)."""
    H = nx.DiGraph()
    H.add_nodes_from(G.nodes(data=True))
    H.add_edges_from((u, v) for u, v, k in G.edges(keys=True) if k in types)
    return H


def lookup(G: nx.MultiDiGraph, name: str, limit: int = 5) -> list[str]:
    """Exact qualified name, then suffix match (`chunk_fixed`, `Index.report`), then fuzzy."""
    if name in G:
        return [name]
    suffix = sorted((n for n in G if n.endswith("." + name)), key=len)
    if suffix:
        return suffix[:limit]
    short = {n.rsplit(".", 1)[-1]: n for n in G}
    return [short[m] for m in get_close_matches(name, list(short), n=limit, cutoff=0.75)]


def call_chains(G: nx.MultiDiGraph, source: str, target: str, k: int = 3) -> list[list[str]]:
    """Up to k shortest call paths source -> ... -> target."""
    calls = edge_view(G, "CALLS")
    try:
        return list(islice(nx.shortest_simple_paths(calls, source, target), k))
    except (nx.NetworkXNoPath, nx.NodeNotFound):
        return []


def impact(G: nx.MultiDiGraph, symbol: str, max_depth: int = 3) -> dict[int, list[str]]:
    """Reverse BFS over CALLS (and INHERITS): who breaks if `symbol` changes, grouped by distance."""
    reverse = edge_view(G, "CALLS", "INHERITS").reverse(copy=False)
    depth = {symbol: 0}
    queue = deque([symbol])
    while queue:
        node = queue.popleft()
        if depth[node] == max_depth:
            continue
        for caller in reverse.successors(node):
            if caller not in depth:
                depth[caller] = depth[node] + 1
                queue.append(caller)
    levels: dict[int, list[str]] = {}
    for node, d in depth.items():
        if d > 0:
            levels.setdefault(d, []).append(node)
    return {d: sorted(ns) for d, ns in sorted(levels.items())}

Complexity: BFS is O(V + E) over the reversed view, so impact on a repository of tens of thousands of symbols is milliseconds; build the views once and cache them in a real service. shortest_simple_paths uses Yen's algorithm and can be slow when many long paths exist; bound k and stop after a timeout.

Why INHERITS is included in impact: if BaseAdapter.send changes its contract, subclasses that override or call it are affected even without a direct call edge. Whether to include IMPORTS is a policy choice; a changed module-level constant affects every importer, but most importers only use one or two names, so including IMPORTS inflates impact sets. Report both and let the user choose.

"""Hybrid code search: identifiers (BM25), docstrings (embeddings) and the call graph, fused with RRF."""
from __future__ import annotations

import re

import networkx as nx

from minigraphrag.embeddings import HashingEmbedder
from minigraphrag.search.bm25 import BM25
from minigraphrag.search.hybrid import reciprocal_rank_fusion
from minigraphrag.vector_store import VectorStore

from .structure import edge_view


def split_identifier(text: str) -> list[str]:
    """chunk_by_sentences -> chunk, by, sentences; TextUnit -> text, unit."""
    words = re.findall(r"[A-Za-z][a-z0-9]*|[A-Z]+(?![a-z])|\d+", text.replace("_", " "))
    return [w.lower() for w in words if len(w) > 1]


def symbol_document(G: nx.MultiDiGraph, node: str) -> str:
    d = G.nodes[node]
    return f"{node} {d.get('signature', '')}\n{d.get('docstring', '')}"


class CodeSearch:
    """BM25 over identifiers + embeddings over docstrings + one hop of call-graph expansion, fused with RRF."""

    def __init__(self, G: nx.MultiDiGraph, embedder=None):
        self.G = G
        self.ids = [n for n, d in G.nodes(data=True) if d.get("kind") != "module"]
        docs = [symbol_document(G, n) for n in self.ids]
        self.bm25 = BM25(docs, tokenizer=split_identifier)
        self.embedder = embedder or HashingEmbedder()
        self.store = VectorStore()
        self.store.add(self.ids, self.embedder.embed(docs), [{"path": G.nodes[n]["path"]} for n in self.ids])
        self.calls = edge_view(G, "CALLS")

    def search(self, query: str, k: int = 8, candidates: int = 30) -> list[tuple[str, float]]:
        keyword = [self.ids[i] for i, _ in self.bm25.search(query, candidates)]
        vector = [sid for sid, _, _ in self.store.search(self.embedder.embed([query])[0], k=candidates)]
        # Graph channel: neighbours of the top textual hits are often the real answer
        # ("where is the budget enforced?" -> the caller of fit_to_budget).
        graph = []
        for sid in (keyword[:3] + vector[:3]):
            graph += [n for n in list(self.calls.predecessors(sid)) + list(self.calls.successors(sid)) if n not in graph]
        return reciprocal_rank_fusion([keyword, vector, graph], k=60, weights=[1.0, 1.0, 0.5])[:k]

With HashingEmbedder, the vector channel is only lexical, so BM25 does most of the work. Swap in a code embedding model through SentenceTransformerEmbedder or an API embedder and embed the source body as well as the docstring to catch undocumented functions; that is where the vector channel starts to add hits BM25 misses. The graph channel's value shows on questions like “where is the token budget enforced?”: the textual hit is fit_to_budget, and its callers in reports are where the budget is actually applied to report context.

Milestone C2.4 Architecture summaries from communities

“How is this package organized?” is the code version of a global question. Answer it the GraphRAG way: cluster the graph and summarize each cluster.

  1. Project the multigraph to an undirected weighted graph. Weight CONTAINS highest (a class and its methods belong together), CALLS and INHERITS next, IMPORTS lowest.
  2. Run louvain_communities from minigraphrag and compute modularity.
  3. For each cluster of at least three symbols, build Entities and Relationships tables in the format reports.py uses and call generate_report.
  4. Record the top modules per cluster so a reader can check the report against the file layout.

"""Architecture summaries: cluster the symbol graph, then write a report per cluster."""
from __future__ import annotations

from collections import Counter

import networkx as nx

from minigraphrag.communities import louvain_communities, modularity
from minigraphrag.context import format_table
from minigraphrag.reports import ENTITY_HEADER, RELATIONSHIP_HEADER, generate_report

EDGE_WEIGHTS = {"CALLS": 1.0, "CONTAINS": 2.0, "INHERITS": 1.0, "IMPORTS": 0.5}


def undirected_projection(G: nx.MultiDiGraph) -> nx.Graph:
    U = nx.Graph()
    U.add_nodes_from(G.nodes(data=True))
    for u, v, k in G.edges(keys=True):
        w = EDGE_WEIGHTS.get(k, 1.0)
        U.add_edge(u, v, weight=U.get_edge_data(u, v, {"weight": 0.0})["weight"] + w)
    return U


def architecture_clusters(G: nx.MultiDiGraph, seed: int = 42) -> tuple[list[set], float]:
    U = undirected_projection(G)
    parts = louvain_communities(U, seed=seed)
    return parts, modularity(U, parts)


def cluster_context(G: nx.MultiDiGraph, members: set, max_rows: int = 40) -> str:
    U = undirected_projection(G)
    ranked = sorted(members, key=lambda n: (-U.degree(n, weight="weight"), n))[:max_rows]
    ents = [[i, n, G.nodes[n]["kind"], (G.nodes[n].get("signature", "") + " " + G.nodes[n].get("docstring", "")[:200]).strip(),
             U.degree(n)] for i, n in enumerate(ranked)]
    rels = [[i, u, v, f"{u.rsplit('.', 1)[-1]} {k.lower()} {v.rsplit('.', 1)[-1]}", U.degree(u) + U.degree(v)]
            for i, (u, v, k) in enumerate((u, v, k) for u, v, k in G.edges(keys=True)
                                          if u in members and v in members and k != "CONTAINS")][:max_rows]
    return format_table("Entities", ENTITY_HEADER, ents) + "\n\n" + format_table("Relationships", RELATIONSHIP_HEADER, rels)


def architecture_reports(G: nx.MultiDiGraph, llm, min_size: int = 3):
    parts, q = architecture_clusters(G)
    reports = []
    for cid, members in enumerate(parts):
        if len(members) < min_size:
            continue
        modules = Counter(n.rsplit(".", 1)[0] if G.nodes[n]["kind"] != "module" else n for n in members)
        report = generate_report(llm, cluster_context(G, members), community_id=cid)
        reports.append({"id": cid, "size": len(members), "top_modules": modules.most_common(3),
                        "title": report.title, "summary": report.summary, "report": report})
    return reports, q

On minigraphrag the reference finds 15 clusters with modularity about 0.75. The largest one mixes context, search.global_ and search.local, because the table-formatting and budgeting helpers in context.py are called by every search method. That is a real architectural fact (context construction is shared infrastructure), and it is exactly what a new contributor needs to hear. The second-largest cluster is the llm module with MockLLM's nineteen handler methods, held together by the CONTAINS edges from one class.

Try the weights: with CONTAINS at 1.0, classes split from their methods more often; with IMPORTS at 1.0, clusters collapse toward modules, which reproduces the directory structure and tells the reader nothing new.

Milestone C2.5 Neo4j and Text2Cypher for structural questions

“Which class in llm.py has the most methods?” and “List functions that call both count_tokens and format_table” are aggregations and pattern matches: a query language answers them exactly. Follow Chapter 20.

  1. Load symbols with UNWIND $rows ... MERGE in batches: a Symbol label plus one of Module, Class, Function, Method, and a uniqueness constraint on id.

import re

import networkx as nx

from minigraphrag.search.text2cypher import validate_cypher

LABELS = {"module": "Module", "class": "Class", "function": "Function", "method": "Method"}
REL_TYPES = ["CONTAINS", "CALLS", "IMPORTS", "INHERITS"]

CODE_SCHEMA = """Node labels: Symbol plus one of Module, Class, Function, Method
Node properties: id (qualified name, e.g. 'minigraphrag.chunking.chunk_fixed'), name (short name), path, lineno, signature, docstring
Relationship types: (Module)-[:CONTAINS]->(Class|Function), (Class)-[:CONTAINS]->(Method),
  (Function|Method)-[:CALLS]->(Function|Method|Class), (Module)-[:IMPORTS]->(Module), (Class)-[:INHERITS]->(Class)"""

CODE_TEXT2CYPHER_PROMPT = """Task: write one read-only Cypher query that answers the question about a Python codebase.
Use only this schema:
{schema}
Rules: MATCH/OPTIONAL MATCH/WHERE/WITH/RETURN/ORDER BY/LIMIT only. Match symbols by `name` or by `id ENDS WITH`.
Always RETURN the `id` of every symbol you list. Return only the query.

Examples:
Question: Which functions call chunk_fixed?

def load_into_neo4j(G: nx.MultiDiGraph, driver, database: str = "neo4j", batch: int = 500) -> None:
    """Idempotent bulk load with UNWIND + MERGE, parameters only (no string-built Cypher)."""
    nodes = [{"id": n, "name": n.rsplit(".", 1)[-1], "label": LABELS[d["kind"]], "path": d["path"],
              "lineno": d["lineno"], "signature": d.get("signature", ""), "docstring": d.get("docstring", "")}
             for n, d in G.nodes(data=True)]
    driver.execute_query("CREATE CONSTRAINT symbol_id IF NOT EXISTS FOR (s:Symbol) REQUIRE s.id IS UNIQUE",
                         database_=database)
    for label in LABELS.values():                       # labels cannot be parameters, so one query per label
        rows = [n for n in nodes if n["label"] == label]
        for i in range(0, len(rows), batch):
            driver.execute_query(
                f"UNWIND $rows AS row MERGE (s:Symbol {{id: row.id}}) SET s:{label}, s += row {{.name, .path, "
                ".lineno, .signature, .docstring}", rows=rows[i:i + batch], database_=database)
    for rel in REL_TYPES:
        rows = [{"u": u, "v": v} for u, v, k in G.edges(keys=True) if k == rel]
        for i in range(0, len(rows), batch):
            driver.execute_query(
                f"UNWIND $rows AS row MATCH (a:Symbol {{id: row.u}}), (b:Symbol {{id: row.v}}) MERGE (a)-[:{rel}]->(b)",
                rows=rows[i:i + batch], database_=database)


def text2cypher(llm, question: str, max_rows: int = 50) -> str:
    raw = llm.complete(CODE_TEXT2CYPHER_PROMPT.format(schema=CODE_SCHEMA, question=question))
    query = re.sub(r"^```(?:cypher)?|```$", "", raw.strip(), flags=re.M).strip().rstrip(";")
    errors = validate_cypher(query, ["Symbol", *LABELS.values()], REL_TYPES)
    if errors:
        raise ValueError("; ".join(errors))
    if not re.search(r"\bLIMIT\s+\d+\s*$", query, re.I):
        query += f" LIMIT {max_rows}"                     # never let a model dump the whole graph
    return query


def answer_structural(llm, driver, question: str, database: str = "neo4j", retries: int = 1) -> dict:
    """Generate, validate, run; on a database error, show the model the error once and retry."""
    feedback = ""
    for attempt in range(retries + 1):
        try:
            query = text2cypher(llm, question + feedback)
            records, _, _ = driver.execute_query(query, database_=database, routing_="r")
            return {"cypher": query, "rows": [r.data() for r in records], "attempts": attempt + 1}
        except Exception as err:                          # validation or Neo4j syntax error
            feedback = f"\n(Your previous query failed with: {str(err)[:300]}. Fix it.)"
    return {"cypher": None, "rows": [], "error": feedback.strip(), "attempts": retries + 1}

Milestone C2.6 The assistant: route, retrieve, answer with file:line

  1. Find code-like tokens in the question (underscores, dots, inner capitals) and resolve them with lookup.
  2. Classify intent: callers, impact, chain (needs two symbols), architecture, structural, or search.
  3. Run the tool; turn its output into a Facts table and the relevant symbols' source into a Sources table with file:line ids.
  4. If the tool produced nothing, fall back to hybrid search and record the fallback in the route name.
  5. Answer with minigraphrag's generate_answer, asking for [Data: Sources (file:line)] citations.

"""Route a question to the right structural tool, build a cited context, and answer."""
from __future__ import annotations

import re

import networkx as nx

from minigraphrag.context import format_table
from minigraphrag.search.common import generate_answer

from .search import CodeSearch
from .structure import call_chains, impact, lookup

IDENT = re.compile(r"`?([A-Za-z_][A-Za-z0-9_]*(?:\.[A-Za-z_][A-Za-z0-9_]*)*)`?")


def mentioned_symbols(G: nx.MultiDiGraph, question: str) -> list[str]:
    found = []
    for token in IDENT.findall(question):
        if "_" in token or "." in token or any(c.isupper() for c in token[1:]):   # looks like code
            found += [s for s in lookup(G, token, limit=1) if s not in found]
    return found


def classify(question: str, symbols: list[str]) -> str:
    q = question.lower()
    if re.search(r"\b(what|which|who)\b.*\bcalls?\b|\bcallers? of\b|\bused by\b", q) and symbols:
        return "callers"
    if re.search(r"\b(break|impact|affected|if i change|depends? on)\b", q) and symbols:
        return "impact"
    if re.search(r"\b(reach|get from|path|chain|lead to|end up)\b", q) and len(symbols) >= 2:
        return "chain"
    if re.search(r"\b(architecture|overview|main (components|parts)|how is .* organi[sz]ed)\b", q):
        return "architecture"
    if re.search(r"\b(how many|list all|count|which classes|largest|most)\b", q):
        return "structural"
    return "search"


def snippet_rows(G: nx.MultiDiGraph, symbols: list[str], max_lines: int = 25) -> list[list]:
    rows = []
    for s in symbols:
        d = G.nodes[s]
        body = "\n".join(d.get("source", "").splitlines()[:max_lines])
        rows.append([f"{d['path'].rsplit('/', 1)[-1]}:{d['lineno']}", s, body.replace("|", "/")])
    return rows


class CodeAssistant:
    def __init__(self, G: nx.MultiDiGraph, llm, reports: list[dict] | None = None, neo4j_driver=None):
        self.G, self.llm, self.reports, self.driver = G, llm, reports or [], neo4j_driver
        self.search = CodeSearch(G)

    def ask(self, question: str) -> dict:
        symbols = mentioned_symbols(self.G, question)
        kind = classify(question, symbols)
        facts, focus = [], []
        if kind in ("callers", "impact"):
            levels = impact(self.G, symbols[-1], max_depth=1 if kind == "callers" else 3)
            for depth, nodes in levels.items():
                facts += [[depth, n, "calls" if depth == 1 else f"reaches it in {depth} hops"] for n in nodes]
            focus = [symbols[-1]] + [n for ns in levels.values() for n in ns][:8]
        elif kind == "chain":
            for i, path in enumerate(call_chains(self.G, symbols[0], symbols[-1])):
                facts.append([i, " -> ".join(p.rsplit(".", 1)[-1] for p in path), " -> ".join(path)])
                focus += [p for p in path if p not in focus]
        elif kind == "architecture":
            facts = [[r["id"], r["title"], r["summary"]] for r in self.reports]
        elif kind == "structural" and self.driver is not None:
            from .cypher import answer_structural
            result = answer_structural(self.llm, self.driver, question)
            facts = [[i, str(row), result["cypher"]] for i, row in enumerate(result["rows"])]
        if kind == "search" or not facts:
            kind = "search" if kind == "search" else f"{kind}->search"
            focus = [s for s, _ in self.search.search(question, k=6)]
        context = format_table("Facts", ["id", "description", "detail"], facts) + "\n\n" + \
            format_table("Sources", ["id", "symbol", "text"], snippet_rows(self.G, focus[:8]))
        answer = generate_answer(self.llm, question, context,
                                 "a short technical answer; cite symbols as [Data: Sources (file:line)]")
        return {"kind": kind, "symbols": symbols, "focus": focus[:8], "facts": facts, "answer": answer}

The table columns are named description and text because those are the columns minigraphrag's answer prompt, and MockLLM, read as evidence. With MockLLM the answer for “What calls count_tokens?” quotes docstrings with citations such as [Data: Sources (tokens.py:33)]; with a real model you get a readable list of callers grouped by module. Keep the Facts table even when the model is strong: it is the deterministic part of the answer and the part your evaluation scores.

Milestone C2.7 Evaluate on a real repository

Grade retrieval, not prose. For each question the gold answer is a set of symbols or a path, checked by hand against the source.

  1. Write at least 30 questions: 8 callers, 6 impact, 6 chain, 6 locate-by-description, 4 structural.
  2. Build gold sets from the source with grep and reading, not from your own tools; otherwise you are testing the tool against itself.
  3. Score set precision, recall and F1 for callers, impact and search; for chains, whether the gold path is returned and whether every returned hop is a real CALLS edge.
  4. Report routing accuracy and list every false negative with its cause.

Checkpoints

"""Score the assistant's retrieval against a hand-checked golden set of code questions."""
from __future__ import annotations

import json
import sys
from pathlib import Path

from .assistant import CodeAssistant
from .parse import parse_repo
from .structure import edge_view


def set_scores(predicted: list[str], gold: list[str]) -> dict:
    p, g = set(predicted), set(gold)
    tp = len(p & g)
    precision = tp / len(p) if p else 0.0
    recall = tp / len(g) if g else 1.0
    f1 = 2 * precision * recall / (precision + recall) if tp else 0.0
    return {"precision": round(precision, 3), "recall": round(recall, 3), "f1": round(f1, 3)}


def valid_chain(G, chain: str) -> bool:
    """Every hop of 'a -> b -> c' must be a real CALLS edge."""
    calls = edge_view(G, "CALLS")
    hops = [h.strip() for h in chain.split("->")]
    return len(hops) > 1 and all(calls.has_edge(a, b) for a, b in zip(hops, hops[1:]))


def evaluate(G, assistant: CodeAssistant, questions: list[dict]) -> list[dict]:
    rows = []
    for q in questions:
        r = assistant.ask(q["question"])
        row = {"id": q["id"], "type": q["type"], "routed": r["kind"], "route_ok": r["kind"] == q["type"]}
        if q["type"] in ("callers", "impact"):
            predicted = [f[1] for f in r["facts"]]
            row.update(set_scores(predicted, q["gold"]))
        elif q["type"] == "chain":
            chains = [f[2] for f in r["facts"]]
            row["valid_chains"] = sum(valid_chain(G, c) for c in chains)
            row["recall"] = float(any(c == " -> ".join(q["gold"]) for c in chains))
        else:  # search / structural: did the right symbols reach the context?
            row.update(set_scores(r["focus"], q["gold"]))
        rows.append(row)
    return rows

Check your understanding

Why does impact analysis traverse CALLS edges in reverse?

  1. Reversed graphs have fewer edges
  2. A change to a function can break the functions that call it, so we follow edges from callee back to callers
  3. NetworkX BFS only works on reversed graphs
  4. Callees are always in other modules
Edges point from caller to callee. The set affected by a change is everything that can reach the changed symbol, which is the forward reachability set in the reversed graph.

call_chains(G, "requests.api.get", "requests.adapters.HTTPAdapter.send") returns nothing, although requests.get does end up sending through the adapter. What is the best description of the problem?

  1. The graph is disconnected because IMPORTS edges are missing
  2. Yen's algorithm cannot find paths longer than three hops
  3. Static resolution cannot type receivers such as a local session or an adapter returned at run time, so those CALLS edges are missing
  4. HTTPAdapter.send is not declared because it is a method
Both missing hops are calls on objects whose class is only known at run time or through assignment. That is the central limitation of static call graphs in dynamic languages.

A golden set's gold callers were generated by running your own impact() function. What is wrong?

  1. Nothing, as long as the function is deterministic
  2. The set is too small
  3. Gold sets must be written in JSON
  4. The evaluation can never reveal the tool's false negatives, because the gold set shares them
Build gold answers independently, from grep and reading the code, so the evaluation measures the tool against reality rather than against itself.

When is Text2Cypher a better tool than a NetworkX traversal in this assistant?

  1. For every question, since databases are faster
  2. For aggregations and ad hoc patterns whose shape you cannot predict, such as counts per class or symbols matching two conditions
  3. For impact analysis, because Cypher supports variable-length paths
  4. Only when the repository is larger than 10,000 files
Known question shapes get deterministic code with no model in the loop. Text2Cypher is for the long tail of structural questions, and it needs validation because the model writes the query.

Questions learners often ask

Why not use an LLM to extract the code graph like we did for Kestrel?

Because the parser is exact, free and fast for the structure it can see. An LLM is useful on top: to describe undocumented functions, to label modules with responsibilities, or to propose likely edges for dynamic dispatch that static analysis misses, marked as inferred. Use the model where the syntax tree runs out.

Should I use a language server or a tool like tree-sitter instead of ast?

For Python only, ast is in the standard library and gives you a complete tree, which is ideal for learning. Tree-sitter parses many languages with one API and tolerates syntax errors, which matters for multi-language repositories and code being edited. Language servers (for example Pyright or Jedi-based ones) add type inference and resolve many of the receiver calls this capstone misses, at the cost of setup and speed. The graph schema and every retrieval tool in this capstone stay the same whichever front end you choose.

How big a repository can this handle?

Parsing is linear in code size and NetworkX comfortably holds hundreds of thousands of nodes in memory. The slow parts are shortest_simple_paths on dense call graphs and embedding every symbol. For very large monorepos, keep the graph in Neo4j, precompute reverse adjacency for impact, embed symbols incrementally, and bound path searches by depth and time.

Is it safe to point this at an untrusted repository?

Parsing with ast.parse does not execute code, so building the graph is safe. The risks are elsewhere: docstrings and comments can contain instructions aimed at the answering model (treat them as untrusted data, as in Chapter 29), and generated Cypher must stay read-only. Never import the analyzed package to “help” resolution.

How does this relate to GraphRAG with community reports?

Directly. Symbols are entities, calls and imports are relationships, docstrings and source are text units, and Louvain clusters with reports are the communities that answer global questions about architecture. The difference is that edges come from a parser instead of an LLM, so structural questions can be answered exactly, and the LLM is left for summarizing and explaining.

Key takeaways

  • A two-pass ast parser recovers modules, classes, functions, methods and their CONTAINS, CALLS, IMPORTS and INHERITS edges with no model.
  • Callers and impact are reverse BFS; call chains are k shortest paths over CALLS only; both are exact within what static analysis sees.
  • Community detection plus minigraphrag's report generator turns the symbol graph into an architecture overview.
  • Text2Cypher covers ad hoc structural questions, with validation, limits and read-only execution.
  • Hybrid search with identifier-aware BM25, embeddings and call-graph expansion finds entry points when no symbol is named.
  • Evaluate against hand-built gold sets; dynamic dispatch and untyped receivers are the main source of false negatives.
