Subgraph retrieval and GNN retrievers

Some questions need more than one path: several constraints that meet at shared entities. This chapter retrieves a small connected subgraph that covers them, using G-Retriever's prize-collecting Steiner tree, then learns just enough about graph neural networks to understand the retrievers that are trained rather than prompted: GRAG, GNN-RAG and GFM-RAG.

You will be able to

  • State the prize-collecting Steiner tree objective and compute it for candidate subgraphs by hand
  • Implement and trace a greedy PCST approximation, and explain where it falls short of an exact solver
  • Describe G-Retriever's pipeline end to end, including the GNN soft prompt
  • Write the message-passing equation, run two layers by hand, and implement a layer in NumPy
  • Explain how GRAG, GNN-RAG and GFM-RAG use trained graph models for retrieval
  • Decide when a trained retriever is worth its data and maintenance cost over training-free methods

From paths to subgraphs

In Chapter 18 the evidence for canonical question 2 was a chain. Look at the question again, though: “Which investor's board member oversees the company whose drones detected the Halden Reef bleaching?” It names a set of constraints: an event, drones, a company, a board member, an investor. The complete evidence is the smallest piece of the graph that satisfies all of them at once:

2024 bleaching -- detected by --> Project Sentinel -- run by --> Kestrel Labs
Kestrel Labs -- board member --> Lena Park -- partner at --> Brightwater Capital
Kestrel Labs -- invested in by --> Brightwater Capital

That is a small tree, not a path, and it includes Kestrel Labs, a node that no word in the question mentions. A retriever that returns the k nodes most similar to the question would likely return the bleaching event, Halden Reef, Brightwater Capital and Lena Park, and miss the company that connects them. A retriever that returns 2-hop neighborhoods would return half the graph. What you want is a principled trade-off: include nodes that are relevant, include connector nodes when they tie relevant nodes together, and pay a price for every edge so the result stays small. That trade-off has a classic name in combinatorial optimization.

G-Retriever and the prize-collecting Steiner tree

G-Retriever (He et al., 2024) targets question answering over textual graphs: graphs whose nodes and edges carry text attributes, such as knowledge graphs, scene graphs and commonsense graphs. The Kestrel entity graph with descriptions is one. Its retrieval step is a four-stage pipeline.

Prizes from similarity

Embed the question with the same model used at indexing, and rank nodes and edges by cosine similarity. G-Retriever does not use the raw similarities as prizes. It assigns rank-based prizes: the top k nodes get prizes k, k − 1, …, 1 and every other node gets 0, and edges are treated the same way. Rank-based prizes avoid depending on the embedding model's similarity scale (one model's “very similar” is 0.9, another's is 0.5), and the zero prize for everything else means non-relevant nodes are only ever included as connectors.

For question 2 with k = 5, a plausible node ranking is: 2024 bleaching event (5), Halden Reef (4), Brightwater Capital (3, “investor”), Lena Park (2, “board member”), Project Sentinel (1, “drones”). Kestrel Labs gets 0: the question describes it (“the company”) without naming anything similar.

The PCST objective

Given node prizes prize(n) ≥ 0 and edge costs Ce > 0, the prize-collecting Steiner tree (PCST) problem asks for a connected subgraph S with node set VS and edge set ES that maximizes

∑n ∈ VS prize(n) + ∑e ∈ ES prize(e) − cost(S),    with   cost(S) = ∑e ∈ ES Ce

Because every edge costs something, the optimal subgraph is always a tree: any cycle has an edge you can drop without disconnecting anything. In G-Retriever, Ce is a single constant chosen per dataset, and it is the knob that sets subgraph size. A cheap edge means “include more connectors”; an expensive edge means “only the densest cluster of prizes survives”.

Edge prizes need one trick, because standard PCST solvers handle only node prizes and non-negative edge costs. If an edge's prize is at most its cost, fold it in as a reduced cost Ce − prize(e). If the prize exceeds the cost, the reduced cost would be negative, so G-Retriever replaces the edge with a virtual node in the middle, gives that node prize prize(e) − Ce, and connects it to both endpoints with zero-cost edges. Including the virtual node is then equivalent to including the edge. Exercise 19.4 implements this.

Solving PCST: exact, fast and greedy

PCST is NP-hard, so no known algorithm solves every instance exactly in polynomial time. There are three practical routes:

  • Exact solvers (integer programming, branch and cut) are fine for hundreds of nodes but unpredictable in running time.
  • Primal-dual approximation in the Goemans–Williamson family has provable approximation guarantees. G-Retriever uses the near-linear-time variant of Hegde, Indyk and Schmidt (2015), which handles graphs with many thousands of edges in milliseconds. If you use G-Retriever's approach in production, use that kind of solver.
  • Greedy heuristics are easy to write and to reason about, with no guarantee. That is what minigraphrag ships, for teaching.

The greedy algorithm grows a tree from the highest-prize node. At each step it computes the shortest path from the current tree to every prized node not yet in it, scores each path by (new prizes along it) − C · (edges in it), and attaches the best path if its gain is positive. When nothing positive remains, it prunes leaves whose prize is below the cost of the edge that holds them.

import networkx as nx
from ..context import format_table
from ..llm import LLM
from .common import DEFAULT_RESPONSE_TYPE, SearchResult, doc_ids_for_units, generate_answer

def similarity_prizes(index, query: str, top_k: int = 10) -> dict[str, float]:
    """Rank-based prizes like G-Retriever: the i-th most similar entity gets prize top_k - i."""
    hits = index.entity_store.search(index.embedder.embed([query])[0], k=top_k)
    return {name: float(top_k - i) for i, (name, _, _) in enumerate(hits)}

def pcst_subgraph(G: nx.Graph, prizes: dict[str, float], edge_cost: float = 1.0, max_nodes: int = 20) -> nx.Graph:
    """Greedy prize-collecting Steiner tree approximation. Returns the selected subgraph (a copy)."""
    candidates = {n: p for n, p in prizes.items() if n in G and p > 0}
    if not candidates:
        return nx.Graph()
    tree = {max(candidates, key=lambda n: (candidates[n], n))}
    tree_edges: set[tuple[str, str]] = set()

    while len(tree) < max_nodes:
        paths = nx.multi_source_dijkstra_path(G, tree)  # shortest path from the tree to every node
        best, best_gain = None, 0.0
        for node, prize in candidates.items():
            if node in tree or node not in paths:
                continue
            path = paths[node]
            new_nodes = [n for n in path if n not in tree]
            gain = sum(prizes.get(n, 0.0) for n in new_nodes) - edge_cost * (len(path) - 1)
            if gain > best_gain and len(tree) + len(new_nodes) <= max_nodes:
                best, best_gain = path, gain
        if best is None:
            break
        tree.update(best)
        tree_edges.update(tuple(sorted(e)) for e in zip(best, best[1:]))

    # Strong pruning: a leaf that costs more to keep than it earns is removed.
    changed = True
    while changed and len(tree) > 1:
        changed = False
        degree = {n: 0 for n in tree}
        for u, v in tree_edges:
            degree[u] += 1
            degree[v] += 1
        for n in list(tree):
            if degree[n] == 1 and prizes.get(n, 0.0) < edge_cost:
                tree.discard(n)
                tree_edges = {e for e in tree_edges if n not in e}
                changed = True

    sub = nx.Graph()
    sub.add_nodes_from((n, G.nodes[n]) for n in tree)
    sub.add_edges_from((u, v, G.edges[u, v]) for u, v in tree_edges)
    return sub

def subgraph_search(index, query: str, llm: LLM, top_k: int = 10, edge_cost: float = 1.0,
                    response_type: str = DEFAULT_RESPONSE_TYPE) -> SearchResult:
    """Retrieve a PCST subgraph and answer from its markdown tables."""
    sub = pcst_subgraph(index.graph, similarity_prizes(index, query, top_k), edge_cost)
    context = "\n\n".join([
        format_table("Entities", ["id", "entity", "description"],
                     [[d.get("human_id"), n, d.get("description", "")] for n, d in sub.nodes(data=True)]),
        format_table("Relationships", ["id", "source", "target", "description"],
                     [[d.get("human_id"), u, v, d.get("description", "")] for u, v, d in sub.edges(data=True)]),
    ])
    units = [u for n in sub.nodes for u in sub.nodes[n].get("source_ids", [])]
    answer = generate_answer(llm, query, context, response_type)
    return SearchResult(answer, "subgraph", context, {"nodes": list(sub.nodes), "edges": list(sub.edges)},
                        doc_ids_for_units(index, units), llm_calls=1)

Trace it on question 2 at cost 1.0. The tree starts at the bleaching event (prize 5).

  1. Candidate paths from the tree: Halden Reef, 1 edge, gain 4 − 1 = 3. Brightwater via Sentinel and Kestrel, 3 edges, gain 1 + 0 + 3 − 3 = 1. Lena Park via the same route, gain 1 + 0 + 2 − 3 = 0. Sentinel, gain 1 − 1 = 0. Attach Halden Reef.
  2. Brightwater still gains 1; Lena Park 0; Sentinel 0. Attach the path through Sentinel and Kestrel Labs to Brightwater. The tree now has five nodes.
  3. Lena Park is now one edge from Kestrel Labs: gain 2 − 1 = 1. Attach.
  4. No prized node remains. Pruning: the leaves Halden Reef (4), Brightwater (3) and Lena Park (2) all have prize ≥ 1, so nothing is removed.

Result: six nodes, five edges, objective 15 − 5 = 10, identical to the optimum. The subgraph's entity and relationship tables go to the LLM as context, exactly as in local search, but the tables now hold a connected explanation instead of a neighborhood.

Two details to check when you adapt this code

First, the tree is returned with tree edges only. For question 2 the tree connects Lena Park and Brightwater both through Kestrel Labs and omits the direct “partner at” edge between them, which is exactly the fact the answer needs. Adding every edge of the induced subgraph among the selected nodes (G.subgraph(sub.nodes)) is a cheap and usually worthwhile change. Second, nx.multi_source_dijkstra_path uses the edge attribute weight as a distance by default. In minigraphrag graphs, weight is summed relationship strength, where higher means stronger, so connecting paths are chosen to minimize strength. Pass weight=None for hop counts, or a function that converts strength into a cost, such as lambda u, v, d: 1 / d["weight"].

From subgraph to generation: the soft prompt

G-Retriever does not stop at a textual context. It encodes the retrieved subgraph with a graph neural network (a graph transformer in the paper), mean-pools the node representations into one vector, and passes it through a small MLP that projects it into the LLM's token-embedding space. That vector is prepended to the embedded input as a graph token, a soft prompt, while the textualized subgraph and the question follow as ordinary tokens. The LLM stays frozen; only the GNN and projection are trained (optionally with LoRA adapters on the LLM as well), on question-answer pairs over graphs.

The two views carry different things. Text carries the attributes precisely (names, dates, descriptions). The graph token carries structure the LLM would otherwise have to reconstruct from a flat list of triples. Training teaches the encoder to summarize the subgraph in whatever way helps the frozen model answer. You need the rest of this chapter's GNN material to read that step, and Chapter 24 returns to soft prompts and graph tokens in depth.

He et al., G-Retriever (2024)

The paper introduces the GraphQA benchmark, which unifies three textual-graph datasets (ExplaGraphs for commonsense reasoning, SceneGraphs for scene understanding and WebQSP for knowledge-graph QA), and shows that retrieval makes QA feasible on graphs too large for the context window. It reports gains over prompt tuning baselines, scaling to larger graphs, and 54% fewer hallucinated nodes and edges in answers than its baseline, because the answer is grounded in a retrieved subgraph rather than in a learned embedding alone.

Graph neural networks, just enough

A graph neural network (GNN) computes a vector for every node by repeatedly mixing each node's vector with its neighbors'. If you have followed PPR in Chapter 17, you already know the core move: one iteration of power iteration pulls mass from neighbors. A GNN layer does the same with vectors instead of scalars, and with learned weights instead of fixed transition probabilities.

Message passing

Almost every GNN fits the message passing template. Let hv(l) be node v's vector after layer l, with hv(0) its input features (for textual graphs, the embedding of its text). One layer computes:

mv(l) = AGGu ∈ N(v) MSG(hu(l), hv(l), euv)

hv(l+1) = UPDATE(hv(l), mv(l))

  • MSG computes what neighbor u tells v, possibly using edge features euv such as the relation text.
  • AGG combines messages with an order-independent function: sum, mean, max or attention-weighted sum. It must not depend on neighbor order, because graphs have none.
  • UPDATE mixes the aggregate with the node's own state, usually a learned linear map and a nonlinearity.

After L layers, hv(L) depends on everything within L hops of v: its receptive field. Two layers see two hops. That is why GNN retrievers for multi-hop QA use as many layers as the hops they need to reason over, and why very deep GNNs struggle: after many rounds of averaging, all node vectors converge toward each other (over-smoothing).

GCN and GAT in one paragraph each

The graph convolutional network (GCN, Kipf and Welling) is the simplest instance. Add self-loops to the adjacency matrix, Â = A + I, normalize symmetrically by degree D̂, and apply a shared weight matrix:

H(l+1) = σ( D̂−1/2 Â D̂−1/2 H(l) W(l) )

Each neighbor's contribution is scaled by 1 / √(deg(u) · deg(v)), so hubs contribute and receive less per edge, the same intuition as PageRank's division by degree. The graph attention network (GAT, Veličković et al.) replaces fixed degree weights with learned attention: for each edge it computes a score from the two nodes' vectors, normalizes scores over each node's neighbors with a softmax, and takes the weighted sum. In a knowledge graph that lets “board member of” matter more than “located in” for a node, depending on its features. Relational GNNs used on knowledge graphs go one step further and condition messages on relation types or relation embeddings.

Two layers by hand

To see the receptive field grow, run a stripped-down GNN with no learned weights: scalar features, mean aggregation over the node and its neighbors, hv(l+1) = (hv(l) + ∑u ∈ N(v) hu(l)) / (1 + deg(v)). Start with a “question signal” of 1 on Project Tern, the entity named in “Why did Kestrel Labs start Project Tern?”, and 0 elsewhere.

A message-passing layer in NumPy

import numpy as np

def gcn_normalize(A: np.ndarray) -> np.ndarray:
    """Â = D^-1/2 (A + I) D^-1/2, the symmetric normalization from Kipf and Welling."""
    A_hat = A + np.eye(len(A))
    d = A_hat.sum(axis=1)
    D_inv_sqrt = np.diag(1.0 / np.sqrt(d))
    return D_inv_sqrt @ A_hat @ D_inv_sqrt

def mean_aggregate(A: np.ndarray) -> np.ndarray:
    """Row-normalized (A + I): each node averages itself and its neighbors."""
    A_hat = A + np.eye(len(A))
    return A_hat / A_hat.sum(axis=1, keepdims=True)

def message_passing_layer(H: np.ndarray, A_norm: np.ndarray, W: np.ndarray, b: np.ndarray | None = None,
                          activation=lambda x: np.maximum(x, 0.0)) -> np.ndarray:
    """One layer: aggregate neighbor features with A_norm, transform with W, apply a nonlinearity.

    H: (n_nodes, d_in) node features. W: (d_out, d_in). Returns (n_nodes, d_out).
    """
    out = A_norm @ H @ W.T
    if b is not None:
        out = out + b
    return activation(out)

if __name__ == "__main__":
    import networkx as nx
    G = nx.Graph([("M", "D"), ("M", "K"), ("M", "P"), ("D", "K"), ("K", "T"), ("P", "T")])
    nodes = list(G)
    A = nx.to_numpy_array(G, nodelist=nodes)
    H = np.array([[1.0 if n == "T" else 0.0] for n in nodes])   # question signal on Project Tern
    W = np.eye(1)                                                # identity weights: pure propagation
    for layer in (1, 2):
        H = message_passing_layer(H, gcn_normalize(A), W)
        print(layer, {n: round(float(v), 3) for n, v in zip(nodes, H[:, 0])})

With learned W and multi-dimensional features, this is a real GCN layer. Training (with PyTorch Geometric or DGL in practice) adjusts W by backpropagating a loss such as “score the answer node highest”. Sparse matrices replace the dense A_norm for real graphs; the arithmetic is identical.

GRAG: retrieving ego-graphs and pruning them softly

PCST selects nodes one at a time from similarity ranks. GRAG (Hu et al., 2024) retrieves whole neighborhoods instead, treating subgraph retrieval as divide and conquer.

  1. Indexing ego-graphs. For every node, take its K-hop ego-graph (the node, everything within K hops, and the edges among them). Embed the text of its nodes and edges with a pretrained language model and mean-pool into one vector per ego-graph. The experiments use K = 1 and K = 2.
  2. Ranking. Embed the question the same way and take the top-N ego-graphs by cosine similarity.
  3. Soft pruning. Inside the retrieved ego-graphs, many nodes are irrelevant. Instead of deleting them with a hard threshold, GRAG learns small MLPs that map the distance between each node's or edge's embedding and the question's embedding to a scaling factor. Irrelevant elements get factors near zero, so they barely influence the GNN encoder, but nothing is hard-deleted.
  4. Merging. The selected ego-graphs are merged into one subgraph.
  5. Dual-view generation. A text view: a hierarchical description of each ego-graph built by BFS, using indentation to preserve topology. A graph view: a GNN over the softly pruned subgraph, projected into the LLM's embedding space as a soft prompt, as in G-Retriever.

On Kestrel, the 1-hop ego-graph of Kestrel Labs is most of the company's story (founders, projects, investor, board member, supplier), and a question about oversight would rank it highly. Soft pruning then dims the founders and supplier and keeps the board member and investor bright. Compared with PCST, ego-graphs retrieve more context around each anchor; compared with local search, the pruning is learned from QA data rather than set by rank and token budget.

Hu et al., GRAG (2024)

GRAG reports significant gains over RAG baselines on multi-hop reasoning over textual graphs, and finds that a frozen LLM given GRAG's retrieved subgraphs through both views outperforms a fine-tuned LLM without retrieval on all its tasks. In its experiments, 2-hop ego-graphs consistently beat 1-hop ego-graphs, which fits the receptive-field argument below: a question that needs two hops of context needs two hops of graph.

GNN-RAG: let a GNN find the answers, let the LLM explain them

GNN-RAG (Mavromatis and Karypis, 2024) splits multi-hop KGQA into what each model is good at. GNNs are good at structured reasoning over a large graph neighborhood: they can score thousands of candidate nodes in one forward pass. LLMs are good at language and at explaining a short chain of facts. So:

  1. Subgraph. Take a dense subgraph of the knowledge graph around the question's entities (the standard KGQA setup on WebQSP and CWQ).
  2. GNN reasoning. A GNN trained for KGQA treats answering as node classification: it outputs, for every node in the subgraph, the probability that it is an answer. The paper uses ReaRev, a GNN whose message passing is conditioned on the question text. Nodes are taken as answer candidates in order of probability until their cumulative probability passes a threshold.
  3. Path extraction. For each candidate, extract the shortest paths in the KG from the question entities to the candidate.
  4. Verbalization and RAG. The paths are written as text, “bleaching event → detected by → Project Sentinel → run by → Kestrel Labs → board member → Lena Park”, and passed to an LLM (the paper fine-tunes a 7B model for this) that reasons over them and answers.

A retrieval augmentation variant unions the GNN's paths with paths retrieved by an LLM-based retriever (the relation-path planner of Reasoning on Graphs). The two find different things: the GNN is strong on multi-hop, multi-entity questions, and the LLM retriever is strong on questions where relation semantics are subtle.

Compare with Chapter 18. Think-on-Graph spends an LLM call on every pruning decision. GNN-RAG spends one GNN forward pass for the whole search, then one LLM call to read the paths. The cost moves from query time to training time: you need a labeled KGQA dataset over your graph's schema to train the GNN.

Mavromatis and Karypis, GNN-RAG (2024)

On the WebQSP and CWQ benchmarks, GNN-RAG reports the best results among the methods compared, and its retrieval-augmented variant matches or outperforms GPT-4 with a tuned 7B LLM as the reader. Its largest gains are on multi-hop and multi-entity questions, 8.9 to 15.5 points over the KG-RAG methods it compares against, which is where GNN reasoning over the whole subgraph helps most compared with LLM-guided step-by-step retrieval.

GFM-RAG: a graph foundation model as the retriever

The trained retrievers above have a practical problem: they are trained per dataset, on one graph and one schema. If your corpus is Kestrel Labs today and a medical corpus tomorrow, you retrain. GFM-RAG (Luo et al., 2025) asks whether a single graph model can be pretrained once and used as a retriever on graphs it has never seen, the way a text embedding model is used on unseen documents.

  • KG-index. Like HippoRAG, it extracts triples from documents with an LLM and adds equivalence edges from entity resolution. An entity-to-document inverted index records which documents mention each entity.
  • Query-dependent GNN. The question is embedded with a sentence encoder. Entities mentioned in the question are initialized with the question embedding; all other entities start at zero. Message passing over the KG, with relation embeddings shaping the messages, spreads the question through the graph for several layers. The final layer scores every entity's relevance to this question. It is PPR's spreading activation with learned, relation-aware, query-conditioned transitions.
  • Document ranking. Entity scores are mapped to documents through the inverted index, with an IDF-style weight that damps entities mentioned everywhere (HippoRAG's node specificity again), so documents mentioning highly scored, specific entities rank first. Like HippoRAG, one retrieval step covers multiple hops.
  • Training. Two stages: self-supervised pretraining on knowledge graph completion (predict masked entities in triples), then supervised fine-tuning on document retrieval with multi-hop QA data. Training uses 60 knowledge graphs with over 14 million triples and about 700,000 documents, and the model has only about 8 million parameters.

Because messages depend on the query and relation embeddings rather than on memorized node identities, the model transfers: nothing in it is tied to a particular entity vocabulary.

Luo et al., GFM-RAG (2025)

GFM-RAG reports the strongest retrieval and QA results among its baselines on three multi-hop QA datasets, and applies to seven domain-specific RAG datasets (including biomedical and customer service) without additional fine-tuning. The authors also report that performance follows a neural scaling pattern with more training data and model size, which is the main argument for calling it a graph foundation model. It appeared at NeurIPS 2025.

Trained retrievers or training-free?

Every method in Chapters 14–18 is training-free: embeddings, graph algorithms and prompted LLMs. This chapter's GNN methods learn part of the retrieval. The choice is an engineering one.

ConcernTraining-free (local search, PPR, PathRAG, PCST, ToG)Trained (G-Retriever, GRAG, GNN-RAG, GFM-RAG)
Data neededNone beyond the corpusQA pairs with answers (and often answer nodes) over your graph, or a pretrained model that transfers
Query-time costCheap (PPR, PCST) to expensive (ToG: many LLM calls)One GNN forward pass plus one LLM call; GPU helps but models are small
Handling schema and graph changesImmediate: new nodes are searchable at onceTransductive models may need retraining; query-conditioned models like GFM-RAG adapt better
Relation semanticsIgnored (PPR, PCST) or delegated to the LLM (ToG)Learned from data, if the training questions cover them
Soft promptsNot applicable; any LLM, including hosted APIsGraph tokens need access to the LLM's embedding layer, so open-weight models only
DebuggabilityHigh: scores and paths are inspectableLower: explain with attention weights or extracted paths
Best fitNew corpora, small teams, changing data, hosted LLMsStable, large KGs with many repeated question types and labeled data (KGQA, enterprise catalogs)

For the Kestrel corpus and most document-derived graphs, start training-free: PCST or PPR retrieval with good linking, evaluated as in Chapter 25. Consider a trained retriever when you have at least thousands of labeled questions over a stable graph, when LLM-walker costs dominate your bill, or when a pretrained graph retriever such as GFM-RAG's checkpoint already transfers to your domain and wins on your evaluation set.

Exercise 19.1 Warm-up

With the prizes from the explorer (bleaching event 5, Halden Reef 4, Brightwater 3, Lena Park 2, Project Sentinel 1, everything else 0) and a uniform edge cost of 1, compute the PCST objective of each node set, or say why it is infeasible: (a) {bleaching, Sentinel, Kestrel Labs, Lena Park}; (b) {bleaching, Halden Reef}; (c) {bleaching, Lena Park}; (d) {bleaching, Halden Reef, Sentinel, Kestrel Labs, Lena Park, Brightwater}; (e) the set in (d) plus Deepcast.

Show answer

The objective for a connected set is total prize minus cost of a spanning tree; with uniform cost that is prizes − (nodes − 1).

  • (a) Connected by bleaching–Sentinel–Kestrel–Lena. Prizes 5 + 1 + 0 + 2 = 8, 3 edges: 5.
  • (b) Connected by one edge. Prizes 9: 8.
  • (c) Infeasible: the bleaching event and Lena Park are not adjacent, and a PCST solution must be connected.
  • (d) Connected (a tree of 5 edges; the induced subgraph also contains Sentinel–Halden and Lena–Brightwater, but a spanning tree needs only 5). Prizes 15: 10.
  • (e) Deepcast adds prize 0 and one edge: 9. A zero-prize leaf always lowers the objective, which is why strong pruning removes such leaves.

Exercise 19.2 Core

Trace pcst_subgraph by hand on the explorer's graph at edge cost 1.4. Then find the optimal subgraph and its objective, and explain in one sentence why greedy misses it. Finally, propose a modification to the greedy algorithm that would find it here.

Hint

Compute the gain of attaching Brightwater and Lena Park separately, then the gain of attaching both together through Sentinel and Kestrel Labs.

Show answer

Start: tree = {bleaching} (prize 5).

  • Halden Reef: 4 − 1.4 = 2.6.
  • Sentinel: 1 − 1.4 = −0.4.
  • Brightwater via Sentinel, Kestrel: 1 + 0 + 3 − 3 × 1.4 = −0.2.
  • Lena Park via Sentinel, Kestrel: 1 + 0 + 2 − 4.2 = −1.2.

Attach Halden Reef. From {bleaching, Halden Reef} every remaining path is the same length (Sentinel is adjacent to both), so the gains are unchanged and all negative. Greedy stops: {bleaching, Halden Reef}, objective 9 − 1.4 = 7.6.

Optimum: {bleaching, Halden Reef, Sentinel, Kestrel Labs, Brightwater, Lena Park}, prizes 15, five edges: 15 − 7 = 8.0. Attaching Sentinel, Kestrel, Brightwater and Lena Park together earns 6 for 4 edges (5.6), a gain of +0.4, but greedy only evaluates one prized target at a time, and the shared connector cost makes each target look unprofitable alone.

A fix that works here: when evaluating a path to one target, also count prized nodes adjacent to the path's new nodes as “attachable for one more edge each” if their prize exceeds the edge cost (a one-step lookahead). Brightwater's path then scores −0.2 + (2 − 1.4) = +0.4 through Lena Park. More principled options are the Goemans–Williamson primal-dual algorithm, which grows clusters around all prized nodes simultaneously, or an exact solver on small retrieved candidate sets.

On the five-node graph from Chapter 17 (edges M–D, M–K, M–P, D–K, K–T, P–T), run two GCN layers by hand with the symmetric normalization D̂−1/2(A + I)D̂−1/2, scalar features (1 on T, 0 elsewhere), identity weights and ReLU. Give every node's value after layers 1 and 2, then compare with mean aggregation. Which normalization gives the hub-adjacent node K more signal, and why?

Degrees with self-loops: M 4, D 3, K 4, P 3, T 3. The weight of edge (u, v) is 1/√(deĝ(u) deĝ(v)).

Layer 1 (only T has signal): T keeps 1/3 = 0.333 (self-loop, 1/√(3·3)); K gets 1/√(4·3) = 0.289; P gets 1/√(3·3) = 0.333; M and D get 0.

Layer 2:

  • M = K/√16 + P/√12 = 0.289/4 + 0.333/3.464 = 0.072 + 0.096 = 0.168
  • D = K/√12 = 0.289/3.464 = 0.083
  • K = K/4 + T/√12 = 0.072 + 0.096 = 0.168
  • P = P/3 + T/3 = 0.111 + 0.111 = 0.222
  • T = K/√12 + P/3 + T/3 = 0.083 + 0.111 + 0.111 = 0.306

Mean aggregation (row-normalized): layer 1 gives K 0.25, P 0.333, T 0.333; layer 2 gives M 0.146, D 0.083, K 0.146, P 0.222, T 0.306. GCN gives K more at layer 1 (0.289 versus 0.25) because symmetric normalization scales by the square root of both degrees: K divides by √4 rather than by 4, and T's small degree boosts what it sends. Exercise 19.4 Core

Implement G-Retriever's edge-prize reduction: with_edge_prizes(G, node_prizes, edge_prizes, edge_cost) returns a graph whose edges carry a cost attribute and a new prize dict, using reduced costs when an edge's prize is at most its cost and virtual nodes otherwise. Write a brute-force exact_pcst(H, prizes) for small graphs, and use both on the question 2 subgraph (bleaching, Sentinel, Halden Reef, Kestrel Labs, Lena Park, Brightwater, Deepcast) at cost 1.4, first with no edge prizes and then with prize 3 on the Lena Park–Brightwater edge (“partner at” is similar to “investor's board member”).

Show answer 
import itertools
import networkx as nx

def with_edge_prizes(G, node_prizes, edge_prizes, edge_cost=1.0):
    H = nx.Graph()
    H.add_nodes_from(G.nodes())
    prizes = dict(node_prizes)
    for u, v in G.edges():
        p = edge_prizes.get((u, v), edge_prizes.get((v, u), 0.0))
        if p <= edge_cost:
            H.add_edge(u, v, cost=edge_cost - p)           # prize folded into a cheaper edge
        else:
            ve = f"e:{u}|{v}"                               # virtual node stands in for the edge
            H.add_edge(u, ve, cost=0.0)
            H.add_edge(ve, v, cost=0.0)
            prizes[ve] = p - edge_cost
    return H, prizes

def exact_pcst(H, prizes):
    best, best_nodes = 0.0, set()
    nodes = list(H.nodes())
    for k in range(1, len(nodes) + 1):
        for S in itertools.combinations(nodes, k):
            sub = H.subgraph(S)
            if not nx.is_connected(sub):
                continue
            cost = sum(d["cost"] for _, _, d in nx.minimum_spanning_edges(sub, weight="cost", data=True))
            value = sum(prizes.get(n, 0.0) for n in S) - cost
            if value > best:
                best, best_nodes = value, set(S)
    return best, best_nodes

G = nx.Graph([("BLEACHING", "SENTINEL"), ("BLEACHING", "HALDEN REEF"), ("SENTINEL", "HALDEN REEF"),
              ("SENTINEL", "KESTREL LABS"), ("KESTREL LABS", "LENA PARK"), ("KESTREL LABS", "BRIGHTWATER"),
              ("LENA PARK", "BRIGHTWATER"), ("KESTREL LABS", "DEEPCAST")])
nodes = {"BLEACHING": 5, "HALDEN REEF": 4, "BRIGHTWATER": 3, "LENA PARK": 2, "SENTINEL": 1}
for edges in ({}, {("LENA PARK", "BRIGHTWATER"): 3.0}):
    H, prizes = with_edge_prizes(G, nodes, edges, edge_cost=1.4)
    print(exact_pcst(H, prizes))

Without edge prizes the optimum is the six-node tree with objective 8.0 (15 − 5 × 1.4), as in Exercise 19.2. With prize 3 on Lena Park–Brightwater, that edge becomes a virtual node with prize 3 − 1.4 = 1.6 joined by two free edges. The optimum keeps the same six real nodes plus the virtual node, objective 11.0: prizes 15 + 1.6 = 16.6, minus four real edges at 1.4 = 5.6. In the original graph that is the tree bleaching–Halden, bleaching–Sentinel, Sentinel–Kestrel, Kestrel–Lena and Lena–Brightwater: prizes 15 + 3 = 18 minus 5 × 1.4 = 7, also 11.0. The reduction preserves the objective, and the “partner at” edge the answer needs is now in the tree instead of Kestrel–Brightwater.

Exercise 19.5 Stretch

Build a GNN-RAG style pipeline on the minigraphrag index without training anything: use Personalized PageRank from the question's linked entities as a stand-in for the GNN's answer probabilities, take nodes as candidates until their cumulative normalized score passes 0.95 (excluding seeds, capped at 5), extract shortest paths from seeds to each candidate, verbalize them with paths_to_text, and answer with one LLM call. Compare the context size in tokens with subgraph_search on question 2. What would a trained GNN add?

Show answer 
import networkx as nx
from minigraphrag.search.ppr import link_query_to_nodes, personalized_pagerank
from minigraphrag.search.paths import paths_to_text
from minigraphrag.search.common import generate_answer
from minigraphrag.search.subgraph import subgraph_search
from minigraphrag.tokens import count_tokens

def gnn_rag_style(index, query, llm, mass=0.95, max_candidates=5, alpha=0.5):
    G = index.graph
    seeds = link_query_to_nodes(index, query, llm)
    scores = personalized_pagerank(G, seeds, alpha=alpha)
    ranked = [(n, s) for n, s in sorted(scores.items(), key=lambda x: -x[1]) if n not in seeds]
    total = sum(s for _, s in ranked) or 1.0
    candidates, cum = [], 0.0
    for n, s in ranked:
        if cum >= mass or len(candidates) == max_candidates:
            break
        candidates.append(n)
        cum += s / total
    paths = []
    for seed in seeds:
        for cand in candidates:
            try:
                paths.append(nx.shortest_path(G, seed, cand))   # hop-count shortest path
            except nx.NetworkXNoPath:
                pass
    context = paths_to_text(G, paths)
    return generate_answer(llm, query, context), context

q = "Which investor's board member oversees the company whose drones detected the Halden Reef bleaching?"
answer, context = gnn_rag_style(index, q, llm)
print(count_tokens(context), "tokens of paths")
print(count_tokens(subgraph_search(index, q, llm).context_text), "tokens of PCST tables")

Path contexts are typically several times smaller than entity and relationship tables for the same question, because they carry only the chains to the candidates. The cap of five candidates matters: PPR mass is spread thinly on a dense graph, so the 0.95 cumulative threshold alone would admit almost every node (a trained GNN's probabilities are much peakier, which is why the paper can use the threshold directly). What training adds: PPR scores every node by proximity regardless of the question's meaning, so hubs and nearby but irrelevant entities become candidates. A GNN like ReaRev conditions its messages on the question and learns from labeled answers which relations lead to answers for which question types, so its candidates are Lena Park and Brightwater Capital rather than Kestrel Labs and Tidewater Institute. The pipeline around it (candidates, shortest paths, verbalization, one LLM call) stays exactly the same.

Check your understanding

In the PCST objective, what does raising the uniform edge cost do to the retrieved subgraph?

  1. It adds more zero-prize connector nodes
  2. It shrinks the subgraph toward the densest cluster of high-prize nodes
  3. It changes the node prizes
  4. It has no effect on connectivity, only on the objective value
Each edge must pay for itself with prizes it connects. Higher costs mean fewer edges are worth it, so distant prizes and connectors drop out. At cost 5 on the question 2 example only the top node survives.

Why does G-Retriever assign rank-based prizes (k, k−1, …, 1) instead of using raw cosine similarities?

  1. Cosine similarity cannot be computed for edges
  2. PCST solvers require integer prizes
  3. Ranks are independent of the embedding model's similarity scale, and everything outside the top k gets exactly zero
  4. It makes the LLM's answer shorter
Similarity values vary by model and query, so a fixed edge cost would mean different things. Ranks give a stable scale, and zero prizes ensure non-relevant nodes appear only as connectors.

An edge has prize 3 and cost 1. How does G-Retriever feed it to a standard PCST solver?

  1. It sets the edge cost to −2
  2. It drops the edge prize
  3. It doubles both endpoints' prizes
  4. It replaces the edge with a virtual node of prize 2 connected to both endpoints by zero-cost edges
Standard solvers do not accept negative costs. The virtual node makes “include the edge” equivalent to “include the node”, with the net prize 3 − 1 = 2.

A GNN retriever has 2 layers. The answer node is 3 hops from the question entity. What happens?

  1. The answer node's final representation cannot depend on the question entity's input signal, so the model cannot identify it through that path
  2. The GNN automatically adds a third layer
  3. Attention lets the signal skip a hop
  4. Nothing: the receptive field of a GNN is the whole graph
After L layers of message passing a node sees only its L-hop neighborhood. In the two-layer walkthrough, Halden Reef, 3 hops from Tern, stayed at 0.

What is the division of labor in GNN-RAG?

  1. The LLM retrieves subgraphs and the GNN writes the answer
  2. The GNN scores nodes as answer candidates over the KG subgraph; shortest paths to them are verbalized for the LLM to reason over
  3. The GNN embeds documents and the LLM runs PCST
  4. The GNN replaces the LLM entirely
GNN-RAG uses a trained GNN (ReaRev) for node classification, extracts shortest paths from question entities to the candidates, and gives those paths to an LLM as retrieval-augmented context.

What property lets GFM-RAG work on graphs it was not trained on?

  1. It memorizes entity embeddings for every possible entity
  2. It fine-tunes on each new dataset automatically at query time
  3. Its GNN is query-dependent: node states start from the question embedding and messages use relation embeddings, not learned per-entity identities
  4. It converts every graph to a fixed schema before retrieval
Nothing in the model is tied to a specific entity vocabulary, so it transfers across graphs. It is pretrained on 60 KGs and reports zero-shot use on seven domain datasets.

Questions learners often ask

Is PCST retrieval better than local search?

It answers a different question. Local search asks “what is around these entities?” and fills a token budget by rank. PCST asks “what is the smallest connected structure that covers the relevant entities?” and can pull in a zero-similarity connector such as Kestrel Labs that local search would include only if it ranked highly. For multi-constraint questions PCST usually gives tighter, more explanatory context; for “tell me about X” questions local search is simpler and just as good.

How do I choose k and the edge cost?

Tune them together on an evaluation set, measuring answer quality and context tokens. A practical start: k between 5 and 15 and a cost that keeps typical subgraphs between 5 and 30 nodes. Because prizes are ranks, a cost around 1 means “an edge must connect roughly a rank-1 node to be worth it”. Log subgraph sizes per query: if many queries return a single node, lower the cost; if subgraphs routinely hit max_nodes, raise it.

Do I need PyTorch Geometric to use any of this?

Not for retrieval. Prizes, PCST, ego-graphs and path extraction are graph algorithms that run with NetworkX. You need a deep learning stack only for the trained parts: the GNN soft prompt in G-Retriever and GRAG, the GNN in GNN-RAG, and running GFM-RAG's pretrained model. All of those papers released code built on PyTorch and PyTorch Geometric.

Can I use a graph soft prompt with a hosted API like Claude or GPT?

No. A soft prompt is a vector inserted into the model's input embedding sequence, which requires access to the model's weights. With hosted APIs you get the text view only: serialize the retrieved subgraph as triples, tables or paths (Chapter 22). The retrieval half of G-Retriever and GRAG works with any LLM.

How is a GNN retriever different from just running PPR?

Both spread a question's signal through the graph for a few hops. PPR's transitions are fixed by topology and weights, and identical for every question. A GNN's transitions are learned and can depend on the question, the node features and the relation type, so it can learn that for “who oversees” questions, “board member of” edges carry signal and “located in” edges do not. The price is training data and a model to maintain. GFM-RAG can be read as a learned, relation-aware generalization of HippoRAG's PPR step.

Key takeaways

  • Multi-constraint questions need a connected subgraph, including connector nodes the question never names.
  • G-Retriever turns similarity ranks into prizes and solves a prize-collecting Steiner tree: maximize prizes minus edge costs, subject to connectivity; the edge cost sets subgraph size.
  • PCST is NP-hard. G-Retriever uses a fast near-linear primal-dual solver; greedy attachment is easy to teach and can miss optima that need several connectors at once.
  • GNNs compute node vectors by message passing; L layers see L hops; GCN normalizes by degree and GAT learns attention over neighbors.
  • GRAG retrieves ego-graphs and prunes softly; GNN-RAG lets a GNN pick answer candidates and an LLM read the shortest paths; GFM-RAG pretrains a query-dependent GNN retriever that transfers across graphs.
  • Start training-free; adopt trained retrievers when you have labeled questions over a stable graph or a pretrained model that wins on your evaluation.
