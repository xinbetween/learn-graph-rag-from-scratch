GraphRAG in one picture

Retrieval-augmented generation (RAG) answers a question by first retrieving relevant material from your own data and then asking a large language model (LLM) to answer from that material, with citations. Classic RAG retrieves text chunks whose embeddings are similar to the question. That works well for lookups (“Who supplied Kestrel's sonar in 2024?”) and poorly for questions whose evidence is scattered (“Why did Kestrel start Project Tern?”) or spread across the whole collection (“What are the main themes here?”).

GraphRAG is the family of methods that put a graph between the documents and the model. At indexing time, an LLM reads the documents and extracts entities (people, organizations, projects) and the relationships between them. Duplicate names are merged, the graph is partitioned into communities of closely connected entities, and each community gets a written summary. At query time, a retriever uses that structure: it starts from the entities a question names and follows edges, or it reads community summaries to answer questions about the whole corpus. The LLM then writes an answer from the retrieved entities, relationships, summaries and source text.

Applied to Kestrel Labs, the graph lets retrieval answer “Why did Kestrel start Project Tern?” by starting at Project Tern, stepping to Deepcast (whose sonar Tern replaces) and on to Marlow Dynamics (which acquired Deepcast), collecting the three facts that explain the decision. Plain vector search, as you will measure in Chapter 3, ranks the article about the acquisition 21st of 24 chunks for that question.

GraphRAG is a family of methods

“GraphRAG” is also the name of Microsoft Research's paper and open-source project, which popularized the approach in 2024. This course uses the word for the whole family: Microsoft-style community summaries, LightRAG's keyword-level retrieval, HippoRAG's Personalized PageRank, path- and subgraph-based retrieval, Text2Cypher over existing knowledge graphs and agentic graph search. You will build a small version of each.

You do not need the history to build anything, but it explains why the field looks the way it does and why so many methods have similar names.

The taxonomy this course follows

With dozens of GraphRAG papers a month, you need a map. This course uses the three-stage structure from the survey by Zhang et al., A Survey of Graph Retrieval-Augmented Generation for Customized Large Language Models, and the curated DEEP-PolyU/Awesome-GraphRAG list organized by it. Every method answers three questions: how is knowledge organized into a graph, how is it retrieved, and how is it integrated into the model's generation?

When you read a new paper, place it on this map first. LightRAG, for example, is mostly an organization choice (entities and relations with keyword descriptions) plus a similarity-based dual-level retriever. Think-on-Graph is an LLM-based, multi-round retriever over an existing knowledge graph. Chapter 33 returns to this map with the papers you have met along the way.

Meet Kestrel Labs

Every example, exercise and project in the course uses one fictional world, so you can watch the same graph grow from raw text to communities to answers. Because it is fictional, no language model knows anything about it: when a model answers a Kestrel question correctly, your retrieval did the work.

Kestrel Labs is an ocean-technology startup in the coastal city of Port Avalon, founded in 2021 by Dr. Mira Okafor (CEO, formerly a researcher at Tidewater Institute) and Jonas Vehl (CTO until March 2026, then Chief Scientist). It builds autonomous underwater drones. Its reef-monitoring program, Project Sentinel, runs with Tidewater Institute as research partner, and in August 2024 its drones detected a mass bleaching event at Halden Reef before divers saw it. Kestrel bought all its sonar from Deepcast until competitor Marlow Dynamics acquired Deepcast in April 2025 and ended outside supply. Kestrel responded with Project Tern, an in-house sonar module co-led by Vehl and Priya Nair, a former Marlow engineer who became CTO in March 2026. Brightwater Capital led Kestrel's Series A ($12M, 2022) and Series B ($40M, 2025); its partner Lena Park sits on Kestrel's board. The regional Ocean Health Act (2025) requires quarterly reef monitoring, which led the Port Avalon City Council to contract Kestrel in November 2025.

Set up the reference code

minigraphrag is a small, readable GraphRAG written for this course: chunking, extraction with gleaning, entity resolution, communities, community reports, eight retrieval methods, Text2Cypher, a bi-temporal graph and evaluation. Chapters show its real code. It depends only on networkx and numpy by default and runs fully offline.

Install

You need Python 3.10 or newer. From the repository root:

cd code
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest -q

-e installs the package in editable mode, so changes you make to minigraphrag/ take effect without reinstalling; several exercises have you edit it. [dev] adds pytest. The test suite should pass in well under a second.

The mock is a teaching device

MockLLM recognizes each course prompt by a marker phrase and answers with deterministic heuristics: a small gazetteer of Kestrel names for extraction, co-occurrence for relationships, and extractive answers that return context sentences with [Data: ...] citations. It shows you what each retriever put into the context, reproducibly and for free. To judge how well a method actually answers, switch to a real LLM.

python -m minigraphrag query --llm anthropic --index .index-claude --method local "Who is the CTO of Kestrel Labs?"

--cache-dir wraps the LLM in CachedLLM, a disk cache keyed by a hash of the model, system prompt, prompt and JSON flag, so rerunning indexing after a code change does not pay for identical calls again. vLLM, LM Studio and other OpenAI-compatible servers work through OPENAI_BASE_URL. For neural embeddings, pass --embedder openai or --embedder st:all-MiniLM-L6-v2 (after installing the st extra); the embedder name is saved in config.json and reused at query time.

The same thing from Python

Most exercises use the Python API directly:

from minigraphrag import HashingEmbedder, IndexConfig, build_index, load_index
from minigraphrag.llm import get_llm
from minigraphrag.search.basic import basic_search
from minigraphrag.search.local import local_search

llm = get_llm("mock")                        # "openai", "anthropic" or "ollama", configured by env vars
build_index("data/corpus", ".index", llm, HashingEmbedder(), IndexConfig(max_gleanings=1), log=print)

index = load_index(".index")
print(index.graph.number_of_nodes(), "entities,", index.graph.number_of_edges(), "relationships")

for search in (basic_search, local_search):
    result = search(index, "Why did Kestrel Labs start Project Tern?", llm)
    print(result.method, result.llm_calls, result.sources)
    print(result.answer[:300], "\n")

Every search method returns a SearchResult with the answer, the method name, the context_text the model saw, structured context_data, the sources (document ids that reached the context) and the number of llm_calls. Comparing sources across methods is the quickest way to see what a retriever found.

Counting calls: the pipeline calls the LLM once per text unit for extraction, plus one “continue extracting” call per unit and gleaning round (with max_gleanings=1 there is no follow-up “anything left?” check, since nothing would be done with the answer), once per unit for claims, once per merged description that needs summarizing, and once per community report. With 24 units that is at least 24 × 3 = 72 calls before summaries and reports. The offline mock run made 122 calls in total. The files in .cache/llm give you the exact number of distinct calls for the real run: one file per call.

What to expect: a real model typically extracts more entities than the mock's gazetteer allows, including things such as the Series A and Series B rounds, the Sentinel sonar array, or the harbour survey firms quoted in articles, and it writes relationship descriptions in its own words rather than copying sentences. Some names will differ in form (“MIRA OKAFOR” vs. “DR. MIRA OKAFOR”), which is why resolution matters. The local answer from a real model should mention the Marlow acquisition if local search pulled in Deepcast's relationships. Rerunning the same command is nearly free thanks to the cache, which is worth verifying: the second run should be fast and make no API calls.

Check your understanding

What distinguishes GraphRAG from classic vector RAG?

  1. GraphRAG does not use an LLM at query time
  2. GraphRAG builds an index of entities, relationships and often community summaries, and retrieval uses that structure
  3. GraphRAG only works with graph databases such as Neo4j
  4. GraphRAG replaces embeddings entirely
The loop is still retrieve-then-generate. What changes is what is indexed and how retrieval navigates it. Most GraphRAG systems still use embeddings, for example to find seed entities.

In the survey taxonomy, where does Personalized PageRank retrieval over an entity graph (HippoRAG) belong?

  1. Knowledge organization
  2. Knowledge integration
  3. Knowledge retrieval
  4. Evaluation
PPR is a way of finding evidence in a graph that already exists. How the graph was built is organization; how the evidence reaches the model's answer is integration.

Why is the Kestrel Labs corpus fictional?

  1. Real documents would be too long to index
  2. Licensing prevents using real news articles
  3. Graph algorithms only work on synthetic data
  4. No model has parametric knowledge of it, so correct answers must come from retrieval
With a real company, a model might answer from memory and hide retrieval failures. The fictional world makes every success and failure attributable.

Canonical question 6, “Who is the CTO of Kestrel Labs?”, is filed as temporal. What makes it hard even with a perfect graph?

  1. The CTO is never named in the corpus
  2. Two people held the role at different times, so the graph needs validity periods to return the current one
  3. CTO is an alias that cannot be resolved
  4. It requires a global summary of the corpus
Jonas Vehl was CTO until March 2026 and Priya Nair since then. Without time on edges, both are “the CTO”.

You run python -m minigraphrag index with no --llm flag and no API keys. What happens?

  1. It fails asking for OPENAI_API_KEY
  2. It downloads a small local model
  3. It runs offline with MockLLM and HashingEmbedder, producing a deterministic index in about a second
  4. It skips extraction and builds only a vector index
The mock is the default so the whole course runs offline and in CI. Use --llm openai|anthropic|ollama for real answers.

What does --cache-dir .cache/llm do?

  1. Stores the index artifacts
  2. Caches embeddings for faster search
  3. Saves query answers for the evaluation harness
  4. Wraps the LLM in CachedLLM, so identical calls (same model, system, prompt, JSON flag) are read from disk instead of paid for again
Indexing makes many calls. Deterministic prompts plus a hash-keyed cache make reruns after code changes cheap.

Questions learners often ask

Do I need to know graph theory or machine learning before starting?

No. You need to be comfortable with Python and with reading short formulas. Chapter 4 teaches the graph ideas you need (adjacency, traversal, shortest paths, PageRank, modularity) from scratch, and Chapter 2 covers embeddings. Chapter 24, on training models with graphs, is the only one that assumes some familiarity with model training, and it is optional on every path except the full one.

Why build from scratch instead of using Microsoft GraphRAG, LightRAG or LlamaIndex?

Because configuration without understanding fails in production: you cannot tune extraction prompts, pick a community level, or explain a bad answer if the pipeline is a black box. The frameworks are good, and Chapter 28 teaches them. After building minigraphrag, you will read their configuration files and source code as variations on things you have already written.

How much will a real LLM cost for the exercises?

For the Kestrel corpus, very little: indexing makes about 120 LLM calls over roughly 5,400 words of source text (122 with the mock and default settings), and a query makes between one and a few dozen calls depending on the method. With a small hosted model this is typically cents to low dollars across the whole course, and --cache-dir means you pay for each distinct call once. A local model through Ollama costs nothing but time. Chapter 26 does the cost math for large corpora, where it matters.

The mock's answers look like copied sentences. Is something broken?

No. The mock answers extractively on purpose: it returns the context sentences that best match the question, each with a [Data: ...] citation. That makes it a window into what the retriever found. If the right sentences appear, retrieval worked; turning them into a well-written answer is the real model's job.

Can I use my own documents instead of Kestrel?

Yes: --input takes any folder of .md files. Do the chapters on Kestrel first, because the exercises and answers refer to it, then rerun your favorite exercises on your own data. You will need a real LLM for that, since the mock's gazetteer only knows Kestrel names.

Project: your workbench and learning journal

Set up the environment you will use for the rest of the course and start a record of the questions you want it to answer.

  • A working code/.venv with pytest -q passing and a mock index in .index/
  • A real-LLM configuration that works (hosted or Ollama), tested with one query --llm ... command and a cache directory
  • A journal.md with the seven canonical questions and at least five questions of your own about Kestrel, each labeled local, global or temporal and multi-hop or not
  • For each journal question, your prediction of whether plain vector RAG will answer it, to check after Chapter 3
  • If you have a real use case, five questions from it with the same labels, and one sentence on why the answers matter

Done when you can build and query an index with both the mock and a real LLM, and your journal has at least twelve labeled questions with predictions.

Key takeaways

  • GraphRAG keeps retrieve-then-generate and adds a graph of entities, relationships and community summaries between documents and the model.
  • The field grew from RAG (2020) through Microsoft's GraphRAG, HippoRAG and LightRAG (2024) to agentic and temporal graph retrieval (2025–2026).
  • Place every method on the map: knowledge organization, knowledge retrieval, knowledge integration.
  • Kestrel Labs is fictional so that every correct answer is earned by retrieval; its seven canonical questions cover multi-hop, global and temporal needs.
  • minigraphrag runs offline with a mock LLM and switches to OpenAI, Anthropic or Ollama with one flag.
  • Choose a learning path, but do not skip Chapter 3.
