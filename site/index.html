Build Graph RAG from scratch.

Vector search finds passages that look like the question. It loses the thread when an answer is spread across documents, when a question is about the whole corpus, or when a fact has changed. This course builds the alternative one stage at a time: extract a graph, cluster it, summarize it, and search it by entities, paths and communities.

Each chapter works one mechanism four ways: a diagram, an interactive figure, graded questions with explanations, and exercises against a small reference implementation you can run offline.

01

Start from where vector search fails.

Multi-hop questions, questions about a whole corpus, and facts that change over time are where plain RAG breaks. Every technique in the course is introduced as a repair for one of those failures.

02

The graph is an index, not the answer.

Entities, relationships, communities and reports exist so retrieval can find the right evidence. Extraction quality, resolution and token budgets decide whether it does.

03

Build it small, then read the frameworks.

Each stage is a short module in minigraphrag. Once you have written it, Microsoft GraphRAG, LightRAG, HippoRAG and Graphiti read as variations on code you already know.
