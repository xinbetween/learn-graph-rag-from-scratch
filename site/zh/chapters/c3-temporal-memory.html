Capstone 3: temporal memory for an agent

An assistant that remembers “Jonas Vehl is our CTO” and never learns that he stepped down will confidently give stale answers for as long as it runs. In this capstone you build a chat agent whose memory is a bi-temporal knowledge graph: it records when each fact was true and when it learned it, retires facts that new ones contradict, and can answer both “who is the CTO?” and “what did I tell you in January?”.

You will be able to

  • Turn conversation turns into episodes and dated facts with an extraction prompt that resolves pronouns and relative dates
  • Store facts as bi-temporal edges on top of minigraphrag.temporal and invalidate contradicted facts without deleting history
  • Detect contradictions with schema rules for single-valued relations and an LLM check for everything else
  • Retrieve memory by fusing semantic, keyword and graph-distance rankings, restricted to the time window and knowledge state a question implies
  • Evaluate memory with a scripted multi-session conversation in which facts change, and compare your design with Graphiti

Overview and architecture

Chapter 27 introduced bi-temporal edges and Chapter 30 showed how Zep and Graphiti use them for agent memory. This capstone builds that memory yourself, small enough to read in one sitting, and tests it against the one change every Kestrel chapter has used: in March 2026 Priya Nair became CTO and Jonas Vehl became Chief Scientist.

The memory has three kinds of objects. An episode is one raw input, such as a chat message, with the time it was received. Entities are people, organizations, projects and job titles. Facts are directed edges between entities, each carrying four timestamps. The names below follow minigraphrag.temporal; Graphiti names the same four valid_at, invalid_at, created_at and expired_at.

Requirements

Functional

  • remember(text, when, session) stores an episode, extracts facts with valid times, resolves entity names, detects contradictions and adds or invalidates edges. Nothing is ever deleted.
  • Single-valued relations are declared in a schema: a person has one HAS_TITLE at a time (source side), a company has one CTO_OF holder at a time (target side). Other contradictions are found by an LLM check over facts that share an endpoint.
  • ask(question, today) derives a valid-time window and, for “what did I tell you” questions, a known-at date; retrieves facts valid in that window with hybrid ranking; and answers with validity periods in the prompt and episode citations.
  • A chat loop in which every statement is remembered and every question is answered.

Evidence

  • A scripted multi-session evaluation with probes for current facts, past facts, record-time (“what did you believe”) facts and facts that are no longer true, run with an oracle extractor and with a real LLM.
  • A comparison with Graphiti on the same script: which probes each system answers, and why.

Constraints

  • Build on minigraphrag.temporal (add_fact, is_valid, parse_date, EXCLUSIVE_RELATIONS), minigraphrag.search.bm25.BM25 and reciprocal_rank_fusion.
  • Dates, not datetimes, are enough for the script; say what changes if you need ordering within a day.
  • Retrieval must never return a fact outside the question's time scope, whatever its similarity.

Milestones

Milestone C3.1 The bi-temporal store

Start with the data structure, tested without any model.

  1. Create a MemoryGraph holding a new_temporal_graph(), a dict of episodes and an alias table. The user is an entity too.
  2. Implement entity(name): normalize with normalize_name; if no exact match, attach a short name to the one known name that contains it (“Jonas” to “Jonas Vehl”).
  3. Implement add(source, relation, target, fact, valid_from, valid_to, episode, contradicts). If an identical open fact exists, attach the episode as extra evidence and stop. For source-exclusive relations, close conflicting open edges. Close the edges listed in contradicts. Then call add_fact, which handles target-exclusive relations such as CTO_OF.
  4. Closing an edge sets prior_valid_to, valid_to and invalidated_at, the three fields is_valid reads for record-time queries, plus invalidated_by so an answer can cite the episode that ended the fact.

"""A bi-temporal memory graph for one user, built on minigraphrag.temporal.

Field names follow minigraphrag.temporal. Graphiti calls the same four timestamps
valid_at (valid_from), invalid_at (valid_to), created_at (recorded_at), expired_at (invalidated_at).
"""
from __future__ import annotations

from dataclasses import dataclass, field
from datetime import date

import networkx as nx

from minigraphrag.resolution import normalize_name
from minigraphrag.temporal import EXCLUSIVE_RELATIONS, add_fact, is_valid, new_temporal_graph, parse_date

# One target per source at a time: a person has one job title, one manager.
SOURCE_EXCLUSIVE = {"HAS_TITLE", "REPORTS_TO", "LIVES_IN"}
# One source per target at a time: a company has one CTO (minigraphrag's EXCLUSIVE_RELATIONS).
TARGET_EXCLUSIVE = set(EXCLUSIVE_RELATIONS)


@dataclass
class Episode:
    id: str
    session: str
    speaker: str
    text: str
    reference_time: date
    fact_keys: list = field(default_factory=list)


class MemoryGraph:
    def __init__(self, user: str):
        self.G: nx.MultiDiGraph = new_temporal_graph()
        self.episodes: dict[str, Episode] = {}
        self.aliases: dict[str, str] = {}          # normalized surface form -> canonical node
        self.user = self.entity(user, "PERSON")

    # ---------------------------------------------------------------- entities
    def entity(self, name: str, etype: str = "") -> str:
        """Resolve a surface form: same normalized name, or the one known name that contains it ("Jonas")."""
        key = normalize_name(name)
        if key in self.aliases:
            node = self.aliases[key]
        else:
            short = [n for k, n in self.aliases.items() if set(key.split()) < set(k.split())]
            node = short[0] if len(short) == 1 else name
            self.aliases[key] = node
        if node not in self.G:
            self.G.add_node(node, type=etype, names=[name])
        elif name not in self.G.nodes[node]["names"]:
            self.G.nodes[node]["names"].append(name)
        return node

    # ---------------------------------------------------------------- facts
    def valid_facts(self, at: date, known_at: date | None = None):
        for u, v, k, d in self.G.edges(keys=True, data=True):
            if is_valid(d, at, known_at):
                yield u, v, k, d

    def invalidate(self, u: str, v: str, key: int, ended: date, learned: date, episode_id: str) -> None:
        """Close an edge's validity at `ended`; keep the old value so record-time queries still work."""
        d = self.G.edges[u, v, key]
        d["prior_valid_to"], d["valid_to"], d["invalidated_at"] = d["valid_to"], ended, learned
        d["invalidated_by"] = episode_id

    def add(self, source: str, relation: str, target: str, fact: str, valid_from, valid_to,
            episode: Episode, contradicts: list[tuple] = ()) -> tuple:
        vf = parse_date(valid_from) or episode.reference_time
        rec = episode.reference_time
        # Duplicate of a fact we already hold? Just attach the episode as extra evidence.
        for u, v, k, d in self.G.edges(keys=True, data=True):
            if (u, v, d["relation"]) == (source, target, relation) and d["invalidated_at"] is None:
                d["episodes"].append(episode.id)
                return (u, v, k)
        # Rule-based contradictions for single-valued relations on the source side.
        if relation in SOURCE_EXCLUSIVE:
            for _, v, k, d in list(self.G.out_edges(source, keys=True, data=True)):
                if d["relation"] == relation and v != target and d["invalidated_at"] is None \
                        and (d["valid_to"] is None or d["valid_to"] > vf):
                    self.invalidate(source, v, k, vf, rec, episode.id)
        # LLM-detected contradictions (see contradictions.py).
        for u, v, k in contradicts:
            if self.G.edges[u, v, k]["invalidated_at"] is None:
                self.invalidate(u, v, k, vf, rec, episode.id)
        # add_fact handles target-side exclusivity (CTO_OF) and stamps recorded_at.
        key = add_fact(self.G, source, relation, target, vf, valid_to, recorded_at=rec, description=fact,
                       exclusive=relation in TARGET_EXCLUSIVE)
        self.G.edges[source, target, key].update(episodes=[episode.id], fact=fact)
        episode.fact_keys.append((source, target, key))
        return (source, target, key)

Why two kinds of exclusivity: add_fact in minigraphrag only knows target-side exclusivity (one CTO per company), which it checks on incoming edges of the target. A job title is exclusive on the source side (one title per person), which needs outgoing edges of the source. Getting this wrong in either direction is a classic bug: treating CO_LEADS as exclusive would make Jonas stop co-leading Tern the moment Priya is recorded as co-lead.

Why the guard d["valid_to"] is None or d["valid_to"] > vf: if an old fact already ended before the new one began (Priya's lead-engineer title ended in March 2026 and a hypothetical later title begins in 2027), there is nothing to contradict.

Milestone C3.2 Extracting dated facts from conversation

Conversation text is harder than news articles: “I”, “our CTO”, “this month” and “the end of June” all need resolving against who is speaking and when.

  1. Write an extraction prompt that gives the speaker's name and the message date, lists preferred relation names, and asks for JSON facts with valid_from and valid_to.
  2. Include the last few turns as context, so “Jonas and I co-lead it” can resolve “it” to Project Tern.
  3. Parse with parse_json_response, drop facts missing a source, relation or target, and normalize relation names to UPPER_SNAKE_CASE.
  4. Test with a stub model before using a real one.

Checkpoints

  • On “Deepcast has supplied our sonar since 2022, but ... supply ends at the end of June” sent on 2025-05-20, a capable model should return SUPPLIED with valid_from 2022 and valid_to 2025-06-30.
  • On “I'm now the CTO of Kestrel Labs” sent on 2026-03-27 by Priya Nair, the source is “Priya Nair”, never “I”.
  • A malformed record in the model's JSON is skipped without losing the others.

"""Turn one conversation turn (an episode) into entities and dated facts."""
from __future__ import annotations

from minigraphrag.llm import parse_json_response

EXTRACT_PROMPT = """You maintain a memory of facts a user tells an assistant.
Speaker: {speaker}. The message was sent on {reference_time}.
Extract facts stated in the message as JSON:
{{"facts": [{{"source": "...", "relation": "UPPER_SNAKE_CASE", "target": "...", "fact": "one sentence",
  "valid_from": "YYYY-MM or YYYY-MM-DD or null", "valid_to": "YYYY-MM or YYYY-MM-DD or null"}}]}}
Rules:
- Replace I/me/my with "{speaker}". Use full names for people and organizations.
- Prefer these relations when they fit: HAS_TITLE (target is a job title), WORKS_AT, LEADS, CO_LEADS,
  CTO_OF, CEO_OF, SUPPLIED, ACQUIRED, INVESTED_IN.
- Resolve relative dates ("this month", "end of June") against the sent date. valid_from is when the
  fact became true, not when it was said; null if unknown.
- Only facts stated in the message. No opinions, no questions.
Recent conversation for context:
{history}
Message:
{text}"""


def extract_facts(llm, speaker: str, text: str, reference_time, history: str = "") -> list[dict]:
    data = parse_json_response(llm.complete(
        EXTRACT_PROMPT.format(speaker=speaker, reference_time=reference_time, history=history or "(none)", text=text),
        json=True))
    facts = []
    for f in data.get("facts", []):
        if all(isinstance(f.get(k), str) and f[k].strip() for k in ("source", "relation", "target")):
            f["relation"] = f["relation"].strip().upper().replace(" ", "_")
            facts.append(f)
    return facts

valid_from is not the message date. “Jonas Vehl is our CTO”, said in May 2025, does not mean he became CTO in May 2025. A careful model returns null; a careless one fills in a year from world knowledge it has no business using. The script's oracle uses 2021 because the running example says so. When valid_from is null, add() falls back to the episode date, which under-states how long the fact has held. That is the safe direction for “who is the CTO now?” and the wrong direction for “who was CTO in 2024?”. Log how often valid times are defaulted.

Milestone C3.3 Contradictions beyond the schema

Schema rules catch job titles and CTOs. They do not catch “These days I spend all my time on Tern” superseding “Most of my time goes to Sentinel”. That needs judgment.

  1. Collect candidate facts: currently valid facts that share an endpoint with the new fact. This keeps the prompt small and the check cheap.
  2. Ask the model which candidates can no longer be true if the new fact is true, stressing that added detail or facts that can hold simultaneously are not contradictions.
  3. Return edge keys for valid ids only, and pass them to add().

Checkpoints

  • With a stub model that flags candidate 0, the Sentinel focus fact gets valid_to 2025-09-01 and invalidated_by ep-2 when the Tern fact arrives.
  • With a real model, “Jonas Vehl co-leads Project Tern” must not invalidate “Priya Nair co-leads Project Tern”; if it does, the prompt's “can hold at the same time” rule is not landing.
  • An out-of-range id in the model's reply is ignored.

"""Ask an LLM which existing facts a new fact makes no longer true."""
from __future__ import annotations

from datetime import date

from minigraphrag.llm import parse_json_response

CONTRADICTION_PROMPT = """New fact (learned {today}): {new_fact}
Existing facts that are currently believed true:
{existing}
Which existing facts can no longer be true if the new fact is true? A fact that adds detail
or can hold at the same time is NOT a contradiction.
Return JSON {{"contradicted": [ids]}}."""


def candidate_facts(memory, source: str, target: str, today: date, limit: int = 10):
    """Only facts that share an endpoint with the new fact can contradict it; this keeps the prompt small."""
    out = []
    for u, v, k, d in memory.valid_facts(today):
        if {u, v} & {source, target}:
            out.append((u, v, k, d))
    return out[:limit]


def find_contradictions(llm, memory, source: str, target: str, fact: str, today: date) -> list[tuple]:
    cands = candidate_facts(memory, source, target, today)
    if not cands:
        return []
    listing = "\n".join(f"[{i}] {d.get('fact') or d['description']} (since {d['valid_from']})"
                        for i, (_, _, _, d) in enumerate(cands))
    data = parse_json_response(llm.complete(
        CONTRADICTION_PROMPT.format(new_fact=fact, existing=listing, today=today), json=True))
    ids = [i for i in data.get("contradicted", []) if isinstance(i, int) and 0 <= i < len(cands)]
    return [(cands[i][0], cands[i][1], cands[i][2]) for i in ids]

Cost: one contradiction call per new fact that has candidates, which dominates write cost in a chatty conversation. Two cheap reductions: skip the call when every candidate's relation is in a known non-exclusive set (such as CO_LEADS), and batch all facts from one episode into a single call. Measure how many invalidations the LLM layer adds beyond the rules; if it is near zero on your traffic, the rules may be enough.

Milestone C3.4 Time-scoped hybrid retrieval

Retrieval has two jobs, in this order: pick the right slice of time, then rank within it.

  1. time_scope(question, today): a month name (without a year, the most recent such month), a year, or nothing (today). If the question asks what the user told the assistant or what it would have said, also set known_at to the end of the window.
  2. Filter edges with an interval-overlap version of is_valid that honors known_at by using prior_valid_to for invalidations the memory had not yet learned.
  3. Rewrite first-person words to the user's name for the text channels.
  4. Rank the surviving facts three ways: embedding similarity, BM25, and hops from the user node in the snapshot graph. Fuse with reciprocal_rank_fusion.

"""Hybrid memory search: semantic + BM25 + graph distance from the user, restricted in time, fused with RRF."""
from __future__ import annotations

import calendar
import re
from datetime import date

import networkx as nx

from minigraphrag.embeddings import HashingEmbedder
from minigraphrag.search.bm25 import BM25
from minigraphrag.search.hybrid import reciprocal_rank_fusion
from minigraphrag.temporal import parse_date

MONTHS = {m.lower(): i for i, m in enumerate(calendar.month_name) if m}
RECALL_CUES = re.compile(r"\b(did i (tell|say)|had i|would you have|did you (know|think)|back then)\b", re.I)


def time_scope(question: str, today: date) -> tuple[date, date, date | None]:
    """(start, end, known_at) implied by the question. Default: now, as currently known."""
    q = question.lower()
    year = re.search(r"\b(20\d\d)\b", q)
    month = next((MONTHS[w] for w in re.findall(r"[a-z]+", q) if w in MONTHS), None)
    if month:
        y = int(year.group(1)) if year else (today.year if month <= today.month else today.year - 1)
        start, end = date(y, month, 1), date(y, month, calendar.monthrange(y, month)[1])
    elif year:
        start, end = date(int(year.group(1)), 1, 1), date(int(year.group(1)), 12, 31)
    else:
        return today, today, None
    # "What did I tell you ... in January" asks about what memory held then, not only what was true then.
    return start, end, (end if RECALL_CUES.search(question) else None)


def valid_during(d: dict, start: date, end: date, known_at: date | None) -> bool:
    valid_to = d["valid_to"]
    if known_at is not None:
        if d["recorded_at"] > known_at:
            return False
        if d["invalidated_at"] is not None and d["invalidated_at"] > known_at:
            valid_to = d["prior_valid_to"]
    return d["valid_from"] <= end and (valid_to is None or start < valid_to)


def search_memory(memory, question: str, today, k: int = 6, embedder=None) -> tuple[list[dict], tuple]:
    today = parse_date(today)
    start, end, known_at = time_scope(question, today)
    facts = [(u, v, key, d) for u, v, key, d in memory.G.edges(keys=True, data=True)
             if valid_during(d, start, end, known_at)]
    if not facts:
        return [], (start, end, known_at)
    # "my title" is about the user: name them so keyword and embedding channels can match.
    query = re.sub(r"\b(I|me|my|mine|myself)\b", memory.user, question, flags=re.I)
    texts = [d.get("fact") or f"{u} {d['relation']} {v}" for u, v, _, d in facts]
    ids = [str(i) for i in range(len(facts))]

    embedder = embedder or HashingEmbedder()
    sims = embedder.embed(texts) @ embedder.embed([query])[0]
    semantic = [ids[i] for i in sims.argsort()[::-1]]
    keyword = [ids[i] for i, _ in BM25(texts).search(query, top_k=len(texts))]
    # Graph distance: facts touching nodes close to the user rank higher ("my role", "our CTO").
    snap = nx.Graph()
    snap.add_nodes_from(memory.G.nodes())
    snap.add_edges_from((u, v) for u, v, _, _ in facts)
    hops = nx.single_source_shortest_path_length(snap, memory.user)
    near = sorted(range(len(facts)), key=lambda i: min(hops.get(facts[i][0], 99), hops.get(facts[i][1], 99)))
    graph = [ids[i] for i in near]

    fused = reciprocal_rank_fusion([semantic, keyword, graph], k=60)
    out = []
    for fid, score in fused[:k]:
        u, v, key, d = facts[int(fid)]
        out.append({"fact": texts[int(fid)], "source": u, "relation": d["relation"], "target": v,
                    "valid_from": str(d["valid_from"]), "valid_to": str(d["valid_to"]) if d["valid_to"] else None,
                    "recorded_at": str(d["recorded_at"]), "episodes": d.get("episodes", []), "score": round(score, 4)})
    return out, (start, end, known_at)

The pronoun rewrite was added after a failing probe, and the failure is worth understanding. “What did I tell you my title was in January?” correctly scoped to January 2026 as known on 31 January, leaving two HAS_TITLE facts: Priya's lead-engineer title and Jonas's CTO title. Without the rewrite, “my title” matches both facts equally in BM25, and with the default HashingEmbedder Jonas's fact ranks first, so the agent answered “CTO”. Replacing “my” with “Priya Nair” lets both text channels prefer her fact, and the graph channel agrees because her own facts are zero hops from the user node.

Why hops from the user help: in personal memory, “our CTO”, “my team” and “my title” are about the user's neighborhood. Graphiti uses the same idea when you pass a center node to its search, reranking by graph distance.

Milestone C3.5 The agent and the chat loop

  1. MemoryAgent.remember: create the episode, extract with recent history, resolve entities, check contradictions, add facts.
  2. MemoryAgent.ask: scope and retrieve, then answer with a system prompt that states today's date, the time window, whether the question is about past knowledge, and every fact with its validity period and episode ids.
  3. A terminal loop: statements are remembered, questions are answered, and a line prefixed on YYYY-MM-DD: replays a past conversation.

Checkpoints

  • Replaying the script through the chat loop with a real model, then asking “Who is the CTO?”, produces an answer that names Priya Nair, mentions the change from Jonas Vehl in March 2026, and cites the episode.
  • The system prompt for “What did I tell you my title was in January?” contains “as remembered on 2026-01-31”.

"""The chat agent: remember every user turn, answer from memory with validity periods in the prompt."""
from __future__ import annotations

from datetime import date

from minigraphrag.temporal import parse_date

from .contradictions import find_contradictions
from .extract import extract_facts
from .graph import Episode, MemoryGraph
from .retrieve import search_memory

ANSWER_SYSTEM = """You are an assistant with long-term memory. Today is {today}.
The question concerns the period {start} to {end}{known}.
Memory facts (each with the period it was true; "until None" means still true):
{facts}
Answer from these facts only. When facts changed over time, say what was true when.
Cite episodes like [ep-3]. If memory has nothing relevant, say you don't know."""


class MemoryAgent:
    def __init__(self, llm, user: str, contradiction_llm=None):
        self.llm, self.memory = llm, MemoryGraph(user)
        self.contradiction_llm = contradiction_llm or llm
        self.history: list[str] = []

    def remember(self, text: str, when, session: str = "s1") -> Episode:
        when = parse_date(when)
        ep = Episode(f"ep-{len(self.memory.episodes) + 1}", session, self.memory.user, text, when)
        self.memory.episodes[ep.id] = ep
        for f in extract_facts(self.llm, self.memory.user, text, when, "\n".join(self.history[-6:])):
            src, tgt = self.memory.entity(f["source"]), self.memory.entity(f["target"])
            contradicted = find_contradictions(self.contradiction_llm, self.memory, src, tgt, f.get("fact", ""), when)
            self.memory.add(src, f["relation"], tgt, f.get("fact", ""), f.get("valid_from"), f.get("valid_to"),
                            ep, contradicted)
        self.history.append(f"{self.memory.user}: {text}")
        return ep

    def ask(self, question: str, today) -> dict:
        today = parse_date(today)
        hits, (start, end, known_at) = search_memory(self.memory, question, today)
        facts = "\n".join(f"- {h['fact']} (true {h['valid_from']} until {h['valid_to']}; "
                          f"learned {h['recorded_at']}) [{', '.join(h['episodes'])}]" for h in hits)
        system = ANSWER_SYSTEM.format(today=today, start=start, end=end, facts=facts or "(none)",
                                      known=f", as remembered on {known_at}" if known_at else "")
        return {"answer": self.llm.complete(question, system=system), "facts": hits,
                "scope": [str(start), str(end), str(known_at) if known_at else None]}

import json

def main(user: str, llm_name: str = "openai", session: str | None = None) -> None:
    agent = MemoryAgent(get_llm(llm_name, cache_dir=".cache/llm"), user)
    session = session or date.today().isoformat()
    print(f"Memory chat for {user}. Prefix a line with 'on YYYY-MM-DD:' to replay an old conversation.")
    for line in sys.stdin:
        text, when = line.strip(), date.today().isoformat()
        if not text:
            continue
        if text.lower().startswith("on ") and ":" in text:
            when, text = text[3:].split(":", 1)
            when, text = when.strip(), text.strip()
        if text.endswith("?"):
            out = agent.ask(text, when)
            print(out["answer"])
            print("  facts used:", json.dumps([f"{h['fact']} [{h['valid_from']}..{h['valid_to']}]" for h in out["facts"]]))
        else:
            ep = agent.remember(text, when, session)
            print(f"  remembered {len(ep.fact_keys)} fact(s) as {ep.id}")

    main(*sys.argv[1:])

The validity periods in the answer prompt do real work. Without them the model sees “Jonas Vehl is the CTO of Kestrel Labs” and “Priya Nair is the CTO of Kestrel Labs” side by side and has to guess. The post-graph-rag paper (Chapter 33) reports the same effect at scale: carrying each relation's validity period through to synthesis was the largest single contribution in its ablation, moving its temporal-reasoning score on LongMemEval from 0.496 to 0.881. You can test the effect on this script by deleting the periods from ANSWER_SYSTEM and re-running the probes with a real model.

Milestone C3.6 The scripted multi-session evaluation

Memory bugs hide in time: a probe passes today and fails after the next session. Evaluate with a fixed script and probes that cover each way time can matter.

  1. Write the script as data: session, date, text, and the facts a careful extractor should produce.
  2. Write probes: current fact, past fact by valid time, past knowledge by record time, a fact about another person, a fact that has ended, and a fact about the user.
  3. Run with an oracle extractor that returns the scripted facts. This isolates memory logic: storage, invalidation and retrieval.
  4. Run again with a real LLM extracting. The difference between the two runs is the extractor's error.
  5. Score the top retrieved fact for the probe's relation, and separately judge the final answers.

Checkpoints

  • All probes pass with the oracle extractor.
  • With a real extractor, a table of which probes fail and whether extraction, contradiction detection or retrieval caused each failure.

class OracleLLM(MockLLM):
    """Returns the scripted facts for extraction prompts; defers everything else to MockLLM."""

    def complete(self, prompt, system=None, json=False):
        if "You maintain a memory of facts" in prompt:
            message = prompt.rsplit("Message:\n", 1)[-1]
            turn = next(t for t in SCRIPT if t["text"] == message.strip())
            return json_dumps({"facts": [dict(zip(["source", "relation", "target", "fact", "valid_from", "valid_to"], f))
                                         for f in turn["facts"]]})
        if "can no longer be true" in prompt:
            return '{"contradicted": []}'    # rules only; the LLM layer is tested separately
        return super().complete(prompt, system=system, json=json)


def json_dumps(obj):
    return json.dumps(obj)


def run(llm) -> list[dict]:
    agent = MemoryAgent(llm, "Priya Nair")
    for turn in SCRIPT:
        agent.remember(turn["text"], turn["when"], turn["session"])
    results = []
    for question, today, expected, relation in PROBES:
        out = agent.ask(question, today)
        matching = [h for h in out["facts"] if h["relation"] == relation]
        got = None
        if matching:
            got = matching[0]["source"] if relation == "CTO_OF" else matching[0]["target"]
            if relation == "SUPPLIED":
                got = matching[0]["source"]
        results.append({"question": question, "scope": out["scope"], "expected": expected, "got": got,
                        "ok": got == expected})
    return results, agent

"""Run the Capstone 3 script through Graphiti (requires graphiti-core, Neo4j, and LLM credentials)."""
import asyncio
from datetime import datetime, timezone

from graphiti_core import Graphiti
from graphiti_core.nodes import EpisodeType

from memory.script_eval import PROBES, SCRIPT


def ts(day: str) -> datetime:
    return datetime.fromisoformat(day).replace(tzinfo=timezone.utc)


async def main():
    graphiti = Graphiti("bolt://localhost:7687", "neo4j", "password")
    try:
        await graphiti.build_indices_and_constraints()
        for i, turn in enumerate(SCRIPT):
            await graphiti.add_episode(
                name=f"{turn['session']}-turn-{i}",
                episode_body=f"Priya Nair: {turn['text']}",
                source=EpisodeType.message,
                source_description="chat with Priya Nair",
                reference_time=ts(turn["when"]),
                group_id="priya",
            )
        for question, asked_on, expected, relation in PROBES:
            edges = await graphiti.search(question, group_ids=["priya"], num_results=8)

            for e in edges:
                print(f"  {e.fact} | valid_at={e.valid_at} invalid_at={e.invalid_at} expired_at={e.expired_at}")

        await graphiti.close()

Check your understanding

In February 2026 the memory held “Jonas Vehl CTO_OF Kestrel Labs” with no end. On 27 March it learned Priya became CTO in March. Asked in April “who would you have said was CTO back in February?”, which fields make the answer Jonas?

  1. valid_from only
  2. invalidated_at after the known-at date, so prior_valid_to (None) is used and the old fact still counts as valid
  3. recorded_at of Priya's fact being in 2026
  4. The graph distance from the user node
Record-time queries roll back invalidations the memory had not learned yet by using the interval end it believed before. Priya's fact is also excluded because its recorded_at is after the known-at date, but that alone would not make Jonas's closed fact count.

Why is HAS_TITLE checked on the source side while CTO_OF is checked on the target side?

  1. minigraphrag only supports one kind
  2. Titles are strings and companies are entities
  3. A person holds one title at a time, while a company has one CTO at a time; the single-valued end of the relation differs
  4. Source-side checks are cheaper
Exclusivity is a property of which end of the relation can have only one partner at a time. Applying it on the wrong end would, for example, stop a person from being CTO whenever anyone else was recorded as CTO of any company.

Why run the scripted evaluation with an oracle extractor before a real LLM?

  1. Because real LLMs cannot extract from chat
  2. To make the tests faster only
  3. Because Graphiti requires it
  4. To isolate storage, invalidation and retrieval bugs from extraction errors, so each failure can be attributed to a component
If the oracle run passes and the real run fails, the extractor is the cause. Without the oracle run, every failure is ambiguous.

A probe “Who supplies our sonar?” asked in April 2026 should return no current supplier. Which design choice guarantees retrieval cannot return the Deepcast fact regardless of similarity?

  1. Giving BM25 a higher weight in fusion
  2. Filtering facts by the question's time scope before any ranking
  3. Lowering the embedding dimension
  4. Adding more episodes about Deepcast
Rankings reorder candidates; only a filter excludes them. Time scoping is a hard constraint, so it runs first.

Questions learners often ask

Why not overwrite the old fact when a new one arrives?

Because the old fact was true, and people ask about the past (“who was CTO when the bleaching was detected?”), about what they said (“what did I tell you in January?”), and about why the assistant changed its answer. Overwriting destroys all three. Invalidation keeps them at the cost of one filter in every query.

How does this differ from summarizing the conversation into the prompt?

A running summary is cheap and works for short relationships, but it loses dates, merges contradictory statements into vague prose, and grows or truncates. A graph memory keeps each fact separately with its time and source episode, so retrieval can pick exactly the facts a question needs and the answer can cite them. Many production agents use both: a short summary for tone and context, a graph for facts.

What if the user is wrong or joking?

Record what was said, not what is true: the memory is a record of the user's statements, which is why episodes are kept and cited. For high-stakes facts, attach a confidence or a status (stated, confirmed, contradicted by a document) in the edge attributes, and phrase answers accordingly (“you told me in May that...”).

Does this scale beyond one user?

The design scales by partitioning: one graph per user or per group, as Graphiti does with group_id. Within a partition, write cost is dominated by the extraction and contradiction calls per message, and read cost by retrieval over that user's facts, which stays small. Move from NetworkX to a database when you need concurrency and persistence, keeping the four timestamps and the query semantics unchanged.

How do I handle relative dates like “last spring”?

Resolve them at write time against the episode's date, in the extraction prompt, and store absolute dates. At read time, time_scope in the reference only handles months and years; for “last spring” or “before Tern started”, either expand the parser or ask the model to output a date range for the question, and validate that range before filtering with it.

Key takeaways

  • Agent memory needs two timelines: when a fact was true and when the agent learned it.
  • New facts close old ones instead of deleting them; prior_valid_to is what makes “what did you believe then” answerable.
  • Declare exclusivity per relation and per end; use an LLM only for contradictions the schema cannot express.
  • Scope by time first, then rank with semantic, keyword and graph-distance signals fused by RRF.
  • Put validity periods into the answer prompt so the model does not have to guess which fact is current.
  • Evaluate with a scripted multi-session conversation, first with an oracle extractor, then with a real one.
