Capstone 1: ship MiniGraphRAG end to end

You have built every stage of GraphRAG in isolation. In this capstone you ship them as one service: index a corpus, answer questions through a router over five retrieval methods behind a streaming API with citations, and write the evaluation and cost report that shows where the graph earns its keep and where it does not.

You will be able to

  • Run the full minigraphrag indexing pipeline on Kestrel and on a corpus you choose, and inspect every artifact it writes
  • Serve basic, local, global, PPR and hybrid search behind one FastAPI service with server-sent events and resolvable citations
  • Build and measure a query router that sends each question to the cheapest method likely to answer it
  • Produce an evaluation report with context recall, token F1 and order-swapped pairwise judging, sliced by question type with intervals
  • Produce a cost report that attributes every token to an indexing stage or query method

Overview and architecture

A GraphRAG demo answers one question well. A GraphRAG service answers every question it is asked, says where its answer came from, costs a known amount, and comes with evidence that it is better than the simpler thing it replaces. That last part is what most projects skip, and it is what this capstone is graded on.

The architecture has two halves. Offline, build_index from Chapter 13 turns Markdown documents into plain artifacts in an out/ folder. Online, a small application package, mgr_app, loads those artifacts once and exposes them over HTTP. Everything that talks to a model goes through a metering wrapper, so the cost report and the evaluation read from the same ledger the service writes to.

Requirements

Functional

  • Index the Kestrel corpus (code/data/corpus) and one corpus of your choice of at least 50 documents or 50,000 words.
  • POST /query accepts {"question", "method"} where method is auto, basic, local, global, ppr or hybrid, and returns the answer, the method used, the router's reason, citations and source documents.
  • POST /query/stream returns the same information as server-sent events: route, sources, a sequence of token events, citations, done.
  • Every citation resolves to a document id and a character span in that document; markers that resolve to nothing are dropped and counted.
  • GET /health reports entity, relationship, community and text unit counts.

Evidence

  • An evaluation report comparing all methods and auto against basic vector RAG, by question type, with context recall, token F1 and pairwise judge win rates with 95% intervals, following Chapter 25: swapped order, inconsistent verdicts counted as ties, answer length reported.
  • A claim you can defend: graph methods beat basic RAG on multi-hop and global questions (or an honest report that they do not on your corpus, with the reason).
  • A cost report: indexing tokens and dollars by stage, and per-query dollars and latency by method.

Constraints

  • Everything runs offline with MockLLM and HashingEmbedder, so tests pass in CI with no keys. Real providers are a configuration change (MGR_LLM=openai).
  • Use minigraphrag's functions for indexing and retrieval; do not fork them. New behavior goes in mgr_app.
  • The judge model must not be the model that generated the answers when you run the real evaluation.
MockLLM numbers prove plumbing, not quality

MockLLM answers by copying sentences that overlap the question, and its judge scores answers with simple counts. Use it to check that every milestone runs end to end and that numbers are computed correctly. Every claim about which method is better must come from a run with real models.

from __future__ import annotations

import json
import sys
from collections import Counter
from pathlib import Path

from minigraphrag.embeddings import get_embedder
from minigraphrag.indexer import IndexConfig, build_index
from minigraphrag.llm import CachedLLM, get_llm

from .metering import MeteredLLM


def main(docs_dir: str = "data/corpus", out_dir: str = "out", llm_name: str = "mock", embedder: str = "hashing"):
    metered = MeteredLLM(get_llm(llm_name))             # counts only calls that reach the provider
    llm = CachedLLM(metered, ".cache/llm")              # re-runs after a crash or code change are free
    index = build_index(docs_dir, out_dir, llm, get_embedder(embedder), IndexConfig(), log=print)
    G = index.graph
    print("entity types:", Counter(d.get("type", "") for _, d in G.nodes(data=True)).most_common())
    print("top entities by degree:", sorted(G.degree, key=lambda x: -x[1])[:5])
    for c in index.communities:
        report = index.report(c.id)
        print(f"community {c.id} (level {c.level}, {len(c.nodes)} nodes): {report.title if report else '-'}")
    print(f"cache hits {llm.hits}, provider calls {llm.misses}")
    Path(out_dir, "build_ledger.json").write_text(json.dumps(metered.snapshot(), indent=1))


if __name__ == "__main__":
    main(*sys.argv[1:])

"""Turn [Data: Sources (a, b); Entities (3)] markers into citations a UI can link."""
from __future__ import annotations

import re

MARKER = re.compile(r"\[Data:([^\]]+)\]")
PART = re.compile(r"(Sources|Entities|Relationships|Reports)\s*\(([^)]*)\)")


def extract_citations(index, answer: str) -> list[dict]:
    G = index.graph
    by_human_node = {d["human_id"]: n for n, d in G.nodes(data=True)}
    by_human_edge = {d["human_id"]: (u, v) for u, v, d in G.edges(data=True)}
    out, seen = [], set()
    for marker in MARKER.finditer(answer):
        for table, ids in PART.findall(marker.group(1)):
            for raw in [i.strip() for i in ids.split(",") if i.strip() and i.strip() != "+more"]:
                key = (table, raw)
                if key in seen:
                    continue
                seen.add(key)
                units = []
                if table == "Sources":
                    units = [raw]
                elif table == "Entities" and raw.isdigit() and int(raw) in by_human_node:
                    units = G.nodes[by_human_node[int(raw)]].get("source_ids", [])
                elif table == "Relationships" and raw.isdigit() and int(raw) in by_human_edge:
                    units = G.edges[by_human_edge[int(raw)]].get("source_ids", [])
                elif table == "Reports" and raw.isdigit():
                    comm = next((c for c in index.communities if c.id == int(raw)), None)
                    units = [u for n in (comm.nodes if comm else []) for u in G.nodes[n].get("source_ids", [])]
                docs = list(dict.fromkeys(index.text_units[u].doc_id for u in units if u in index.text_units))
                if not docs:
                    continue  # a marker that points at nothing is dropped, and counted by the eval
                first = index.text_units.get(units[0]) if units else None
                out.append({"table": table, "id": raw, "doc_ids": docs[:5],
                            "snippet": first.text[:200] if first else "",
                            "span": [first.start, first.end] if first else None})
    return out

"""One entry point for every method, used by the API, the evaluator and the cost report."""
from __future__ import annotations

import time
from contextlib import nullcontext

from minigraphrag.search.basic import basic_search
from minigraphrag.search.global_ import global_search
from minigraphrag.search.hybrid import hybrid_search
from minigraphrag.search.local import local_search
from minigraphrag.search.ppr import hipporag_search

from .citations import extract_citations
from .router import route

METHODS = {
    "basic": lambda index, q, llm: basic_search(index, q, llm),
    "local": lambda index, q, llm: local_search(index, q, llm),
    "global": lambda index, q, llm: global_search(index, q, llm, dynamic=False),
    "ppr": lambda index, q, llm: hipporag_search(index, q, llm),
    "hybrid": lambda index, q, llm: hybrid_search(index, q, llm),
}


def run_method(index, llm, question: str, method: str):
    tag = llm.tagged(f"query:{method}") if hasattr(llm, "tagged") else nullcontext()
    with tag:
        return METHODS[method](index, question, llm)


def answer(index, llm, question: str, method: str = "auto") -> dict:
    t0 = time.perf_counter()
    decision = route(index, question, llm) if method == "auto" else None
    chosen = decision.method if decision else method
    result = run_method(index, llm, question, chosen)
    return {"question": question, "method": chosen,
            "route_reason": decision.reason if decision else "forced",
            "answer": result.answer, "citations": extract_citations(index, result.answer),
            "sources": result.sources, "llm_calls": result.llm_calls,
            "latency_ms": round(1000 * (time.perf_counter() - t0), 1)}

Two design decisions to notice. The router runs inside answer() so that auto is evaluated exactly as it is served. And global search is called with dynamic=False because the Kestrel hierarchy has one level; on a larger corpus, try dynamic=True (dynamic community selection from Chapter 15) and record the call counts in M7.

Milestone C1.4 The query router

Global search costs a map call per batch of reports and is poor at “Who directs Tidewater Institute?”. Basic search is cheap and poor at “What are the main themes?”. A router picks per question. Build the cheapest one that works and measure it.

  1. Find named entities in the question with map_query_to_entities and keep only those whose name actually appears.
  2. Rules: sensemaking cues with at most one named entity go to global; multi-hop cues or three or more entities go to ppr; one or two named entities go to local.
  3. If no rule fires, ask the LLM for a JSON route; if that fails, use hybrid.
  4. Measure routing accuracy against the type labels in questions.jsonl, then write 15 new questions and measure again.

"""Pick a retrieval method per question: cheap rules first, an LLM only when the rules are unsure."""
from __future__ import annotations

import re
from dataclasses import dataclass

from minigraphrag.llm import parse_json_response
from minigraphrag.search.local import map_query_to_entities

GLOBAL_CUES = re.compile(r"\b(main themes?|overall|summari[sz]e|trends?|risks?|landscape|evolved|big picture|role does)\b", re.I)
MULTIHOP_CUES = re.compile(r"\b(why|connect(s|ed|ion)?|relat(e|ed)|whose|path|link(ed)?|previously|used by|"
                           r"the company that|both|and how)\b", re.I)
TEMPORAL_CUES = re.compile(r"\b(19|20)\d\d\b|\b(as of|when|currently|now|before|after|since)\b", re.I)

ROUTER_PROMPT = """Classify the question for a GraphRAG system. Routes:
- "global": asks about themes, trends or a summary across the whole corpus
- "ppr": needs a chain of facts across several entities (multi-hop)
- "local": about one or two named entities and their direct facts
- "basic": a narrow factual lookup likely answered by one passage
Return JSON {{"route": "...", "reason": "..."}}.
Question: {question}"""


@dataclass
class Route:
    method: str
    reason: str
    entities: list[str]


def route(index, question: str, llm=None) -> Route:
    named = [e for e in map_query_to_entities(index, question, top_k=5, include_name_matches=True)
             if re.search(re.escape(e.split()[-1]), question.upper())]
    if GLOBAL_CUES.search(question) and (len(named) <= 1 or question.lower().startswith("summari")):
        return Route("global", "sensemaking cue with at most one named entity", named)
    if MULTIHOP_CUES.search(question) or len(named) >= 3:
        return Route("ppr", f"multi-hop cue or {len(named)} named entities", named)
    if named:
        why = "temporal lookup on a named entity" if TEMPORAL_CUES.search(question) else "named-entity lookup"
        return Route("local", why, named)
    if llm is not None:
        choice = parse_json_response(llm.complete(ROUTER_PROMPT.format(question=question), json=True))
        if choice.get("route") in {"global", "ppr", "local", "basic"}:
            return Route(choice["route"], "llm: " + str(choice.get("reason", "")), named)
    return Route("hybrid", "no confident signal; fuse everything", named)

Milestone C1.5 A streaming API

Global search can take many seconds with a real model. Users tolerate waiting when they see progress, so stream it. Server-sent events (SSE) are plain HTTP: the response is text/event-stream and each event is an event: line, a data: line and a blank line.

"""FastAPI service: POST /query for JSON, POST /query/stream for server-sent events."""
from __future__ import annotations

import json
import os
from typing import Literal

from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from pydantic import BaseModel

from minigraphrag.indexer import load_index
from minigraphrag.llm import get_llm

from .metering import MeteredLLM
from .service import answer, run_method
from .router import route
from .citations import extract_citations

INDEX_DIR = os.getenv("MGR_INDEX", "out")
index = load_index(INDEX_DIR)
# No response cache here: identical questions should still reach the model, and the meter must see real spend.
llm = MeteredLLM(get_llm(os.getenv("MGR_LLM", "mock")), price_key=os.getenv("MGR_PRICE", "mock"))
app = FastAPI(title="MiniGraphRAG")


class Query(BaseModel):
    question: str
    method: Literal["auto", "basic", "local", "global", "ppr", "hybrid"] = "auto"


@app.get("/health")
def health():
    G = index.graph
    return {"entities": G.number_of_nodes(), "relationships": G.number_of_edges(),
            "communities": len(index.communities), "text_units": len(index.text_units)}


@app.post("/query")
def query(q: Query):
    return answer(index, llm, q.question, q.method)


def _sse(event: str, data) -> str:
    return f"event: {event}\ndata: {json.dumps(data)}\n\n"


def _stream_text(text: str, size: int = 24):
    # minigraphrag's LLM interface returns whole strings. If your client supports token
    # streaming, yield its deltas here instead; the event protocol stays the same.
    for i in range(0, len(text), size):
        yield text[i:i + size]


@app.post("/query/stream")
def query_stream(q: Query):
    def events():
        decision = route(index, q.question, llm) if q.method == "auto" else None
        method = decision.method if decision else q.method
        yield _sse("route", {"method": method, "reason": decision.reason if decision else "forced"})
        result = run_method(index, llm, q.question, method)
        yield _sse("sources", {"doc_ids": result.sources})
        for delta in _stream_text(result.answer):
            yield _sse("token", {"text": delta})
        yield _sse("citations", extract_citations(index, result.answer))
        yield _sse("done", {"llm_calls": result.llm_calls, "cost_usd": round(llm.cost(), 6)})
    return StreamingResponse(events(), media_type="text/event-stream")

The reference streams the finished answer in chunks because minigraphrag's LLM.complete returns a whole string. The events that matter most for perceived latency, route and sources, already arrive before generation starts. Milestone C1.6 The evaluation report

This is the milestone that turns a demo into an argument. Follow the methodology from Chapter 25.

  1. For each of the 23 questions, run basic, local, global, ppr, hybrid and auto.
  2. Compute context recall against supporting_docs and token F1 against the gold answer with minigraphrag's context_recall and token_f1.
  3. For every non-basic answer, run llm_judge_pairwise against the basic answer on the four criteria. It asks twice with the order swapped and keeps a winner only when both orders agree. Score a win 1, a tie or inconsistent pair 0.5, a loss 0.
  4. Report the mean win rate per method and question type with a 95% bootstrap interval over questions, next to recall, F1 and calls.
  5. With real models: use a different, stronger judge than the generator, cache judge calls, and report mean answer length per method, since comprehensiveness and diversity reward longer answers.

"""Evaluation report: context recall and token F1 per method, pairwise judge win rates against basic RAG."""
from __future__ import annotations

import json
import random
import sys
from collections import defaultdict
from pathlib import Path

from minigraphrag.evaluation import context_recall, llm_judge_pairwise, load_questions, token_f1

from .service import answer

CRITERIA = ("comprehensiveness", "diversity", "empowerment", "directness")
POINTS = {"A": 1.0, "TIE": 0.5, "B": 0.0}


def bootstrap_ci(values: list[float], n: int = 2000, seed: int = 0) -> tuple[float, float]:
    """95% percentile bootstrap interval of the mean (resampling questions)."""
    rng = random.Random(seed)
    means = sorted(sum(rng.choice(values) for _ in values) / len(values) for _ in range(n))
    return means[int(0.025 * n)], means[int(0.975 * n) - 1]


def run(index, llm, judge, questions, methods=("basic", "local", "global", "ppr", "hybrid", "auto")) -> list[dict]:
    rows = []
    for q in questions:
        results = {m: answer(index, llm, q["question"], m) for m in methods}
        baseline = results["basic"]["answer"]
        for m, r in results.items():
            row = {"id": q["id"], "type": q["type"], "method": m, "routed_to": r["method"],
                   "recall": context_recall(r["sources"], q.get("supporting_docs", [])),
                   "f1": token_f1(r["answer"], q["answer"]),
                   "citations": len(r["citations"]), "llm_calls": r["llm_calls"]}
            if m != "basic":
                # The candidate is always answer A; llm_judge_pairwise asks again with the order
                # swapped and only keeps a winner both orders agree on.
                verdicts = llm_judge_pairwise(judge, q["question"], r["answer"], baseline, CRITERIA)
                row.update({c: POINTS[verdicts[c]["winner"]] for c in CRITERIA})
            rows.append(row)
    return rows


def report(rows: list[dict]) -> str:
    groups = defaultdict(list)
    for r in rows:
        groups[(r["type"], r["method"])].append(r)
    out = ["| question type | method | n | context recall | token F1 | win rate vs basic [95% CI] |",
           "|---|---|---|---|---|---|"]
    for (qtype, method), rs in sorted(groups.items()):
        recall = sum(r["recall"] for r in rs) / len(rs)
        f1 = sum(r["f1"] for r in rs) / len(rs)
        if method == "basic":
            win = "(baseline)"
        else:
            per_q = [sum(r[c] for c in CRITERIA) / len(CRITERIA) for r in rs]
            lo, hi = bootstrap_ci(per_q)
            win = f"{sum(per_q) / len(per_q):.2f} [{lo:.2f}, {hi:.2f}]"
        out.append(f"| {qtype} | {method} | {len(rs)} | {recall:.2f} | {f1:.2f} | {win} |")
    return "\n".join(out)

"""Count every LLM call, its tokens and its cost, tagged with the pipeline stage."""
from __future__ import annotations

import time
from collections import defaultdict
from contextlib import contextmanager

from minigraphrag import prompts as P
from minigraphrag.tokens import count_tokens

# USD per million tokens. Placeholders: copy your provider's current price sheet.
PRICES = {"mock": (0.0, 0.0), "gpt-4o-mini": (0.15, 0.60), "local": (0.0, 0.0)}


class MeteredLLM:
    """Wraps any minigraphrag LLM. Same complete() signature, plus a ledger."""

    def __init__(self, llm, price_key: str = "mock"):
        self.llm, self.price_key = llm, price_key
        self.name = getattr(llm, "name", type(llm).__name__)
        self.stage = "unlabelled"
        self.ledger = defaultdict(lambda: {"calls": 0, "in": 0, "out": 0, "seconds": 0.0})

    @contextmanager
    def tagged(self, stage: str):
        previous, self.stage = self.stage, stage
        try:
            yield self
        finally:
            self.stage = previous

    def complete(self, prompt: str, system: str | None = None, json: bool = False) -> str:
        t0 = time.perf_counter()
        out = self.llm.complete(prompt, system=system, json=json)
        stage = self.stage
        if stage == "unlabelled" or stage.startswith("query:"):
            # Name the job from the prompt's marker (same trick MockLLM uses): extraction, report, map...
            task = next((t for t, m in P.MARKERS.items() if m in f"{system or ''}\n{prompt}"), "other")
            stage = task if stage == "unlabelled" else f"{stage}/{task}"
        row = self.ledger[stage]
        row["calls"] += 1
        row["in"] += count_tokens(prompt) + count_tokens(system or "")
        row["out"] += count_tokens(out)
        row["seconds"] += time.perf_counter() - t0
        return out

    def cost(self, stage: str | None = None) -> float:
        p_in, p_out = PRICES[self.price_key]
        rows = [self.ledger[stage]] if stage else self.ledger.values()
        return sum(r["in"] * p_in + r["out"] * p_out for r in rows) / 1e6

    def snapshot(self) -> dict:
        return {k: dict(v) for k, v in self.ledger.items()}
"""Index a corpus through a metered LLM, run the question set, and write cost_report.md."""
from __future__ import annotations

import json
import statistics
import sys
import time
from collections import defaultdict
from pathlib import Path

from minigraphrag.chunking import load_documents
from minigraphrag.indexer import IndexConfig, build_index
from minigraphrag.llm import CachedLLM, get_llm
from minigraphrag.tokens import count_tokens

from minigraphrag.evaluation import load_questions
from .metering import MeteredLLM
from .service import answer


def pct(values, q):
    values = sorted(values)
    return values[min(len(values) - 1, int(q * len(values)))]


def main(docs_dir: str, out_dir: str, llm_name: str = "mock", price_key: str = "mock"):
    # Meter *inside* the cache: cache hits cost nothing, so the ledger shows real provider spend.
    llm = MeteredLLM(get_llm(llm_name), price_key)
    corpus_tokens = sum(count_tokens(t) for t in load_documents(docs_dir).values())
    t0 = time.perf_counter()
    index = build_index(docs_dir, out_dir, CachedLLM(llm, ".cache/llm"), config=IndexConfig())
    index_seconds = time.perf_counter() - t0
    index_ledger = llm.snapshot()
    index_cost = llm.cost()

    per_method = defaultdict(list)
    for q in load_questions("data/questions.jsonl"):
        for method in ("basic", "local", "global", "ppr", "hybrid", "auto"):
            before = llm.cost()
            r = answer(index, llm, q["question"], method)
            per_method[method].append((llm.cost() - before, r["latency_ms"], r["llm_calls"]))

    lines = [f"# Cost report ({llm.name}, prices: {price_key})", "",
             f"Corpus: {corpus_tokens:,} tokens, {len(index.text_units)} text units. "
             f"Indexing took {index_seconds:.1f}s and cost ${index_cost:.4f} "
             f"(${1e6 * index_cost / max(corpus_tokens, 1):.2f} per million corpus tokens).", "",
             "| indexing stage | calls | input tokens | output tokens |", "|---|---|---|---|"]
    for stage, row in sorted(index_ledger.items(), key=lambda x: -x[1]["in"]):
        lines.append(f"| {stage} | {row['calls']} | {row['in']:,} | {row['out']:,} |")
    lines += ["", "| query method | mean $/query | p50 ms | p95 ms | LLM calls/query |", "|---|---|---|---|---|"]
    for method, xs in per_method.items():
        costs, lat, calls = zip(*xs)
        lines.append(f"| {method} | {statistics.mean(costs):.5f} | {pct(lat, .5):.0f} | {pct(lat, .95):.0f} | "
                     f"{statistics.mean(calls):.1f} |")
    Path("cost_report.md").write_text("\n".join(lines))
    Path("cost_ledger.json").write_text(json.dumps(llm.snapshot(), indent=1))
    print("\n".join(lines))


if __name__ == "__main__":
    main(*sys.argv[1:])

"""Milestone 8: turn .txt, .html and .md files into the Markdown folder build_index expects."""
from __future__ import annotations

import html
import re
import sys
from pathlib import Path


def html_to_text(raw: str) -> str:
    raw = re.sub(r"(?is)<(script|style|nav|footer|header)\b.*?</\1>", " ", raw)
    raw = re.sub(r"(?i)<h([1-3])[^>]*>", lambda m: "\n\n" + "#" * int(m.group(1)) + " ", raw)
    raw = re.sub(r"(?i)</(p|div|li|h[1-6]|tr)>|<br\s*/?>", "\n", raw)
    text = html.unescape(re.sub(r"<[^>]+>", " ", raw))
    return re.sub(r"[ \t]+", " ", re.sub(r"\n\s*\n+", "\n\n", text)).strip()


def prepare(src: str, dst: str, min_words: int = 50) -> None:
    out = Path(dst)
    out.mkdir(parents=True, exist_ok=True)
    kept = skipped = 0
    for path in sorted(Path(src).rglob("*")):
        if path.suffix.lower() not in {".md", ".txt", ".html", ".htm"}:
            continue
        raw = path.read_text(encoding="utf-8", errors="replace")
        text = html_to_text(raw) if path.suffix.lower() in {".html", ".htm"} else raw
        if len(text.split()) < min_words:
            skipped += 1
            continue
        # The file stem becomes the doc_id used in every citation, so make it stable and readable.
        stem = re.sub(r"[^a-z0-9]+", "_", str(path.relative_to(src).with_suffix("")).lower()).strip("_")
        (out / f"{stem}.md").write_text(f"# {path.stem}\n\n{text}\n", encoding="utf-8")
        kept += 1
    print(f"wrote {kept} documents to {out} (skipped {skipped} shorter than {min_words} words)")


if __name__ == "__main__":
    prepare(*sys.argv[1:3])

Check your understanding

Why does the reference put MeteredLLM inside CachedLLM rather than outside it?

  1. The cache needs token counts to build its keys
  2. So the ledger counts only calls that reach the provider, which is what you pay for
  3. So that cached responses are re-metered on every run for accuracy
  4. MeteredLLM cannot wrap objects that have a hits attribute
Wrapped outside the cache, the meter would count cache hits as spend, and a re-run would appear to cost as much as the first run.

Global search shows context recall 1.00 on global questions while basic search shows 0.37. What is the right conclusion?

  1. Global search is proven better on global questions
  2. Basic search has a bug
  3. Recall is inflated for global search because its sources include documents behind every community used, so judge the answers pairwise instead
  4. Context recall should be replaced by exact match
Retrieving nearly everything guarantees recall. For sensemaking questions, compare answers with order-swapped pairwise judging and report the interval.

The router scores 22/23 on the labelled questions after its cue lists were extended based on its misses. Which number belongs in the report?

  1. 22/23, because it is the latest measurement
  2. The score from before the cue lists were extended
  3. The average of the two
  4. Accuracy on new questions written after the rules were frozen, alongside 22/23 labelled as a training score
Rules tuned on the evaluation questions overfit them. Held-out accuracy estimates how the router will behave on real traffic.

In the stream, why does the route event come before generation even though the reference streams the finished answer in chunks?

  1. SSE requires the first event to be metadata
  2. The router decides in milliseconds, so the client can show progress and the chosen method while slow retrieval and generation run
  3. FastAPI sends events in alphabetical order
  4. The route determines the HTTP status code
Perceived latency depends on the time to first useful feedback. Route and sources arrive early; token events follow.

Questions learners often ask

Why FastAPI with SSE instead of WebSockets?

A question produces one stream of events in one direction, which is exactly what SSE is for. It is plain HTTP, works through most proxies, is trivial to test with curl -N, and browsers reconnect automatically with EventSource. Use WebSockets when the client needs to send messages mid-stream, for example to cancel or refine a query, as a chat agent might in Capstone 3.

The judge prefers global search on almost everything, including single-hop questions. Is the judge broken?

Probably biased rather than broken. Comprehensiveness and diversity reward longer answers, and map-reduce produces longer answers. Check three things: that the order swap is on (inconsistent verdicts become ties), that both systems use the same response_type, and the mean answer length per method. If global still wins on single-hop questions on directness, look at the answers yourself; if it does not deserve to, calibrate the judge on 20 pairs you label by hand and report the agreement.

Should the router use an LLM for every question?

Not by default. A routing call adds latency and cost to every request, while rules decide most questions correctly for free. Use the LLM only when rules do not fire, and log how often that happens. If the fallback rate is high on real traffic, collect those questions and either add rules or train a small classifier on logged, labelled routes.

How do I serve an index that is rebuilt while the service is running?

Build into a new directory, then switch atomically: point a symlink such as out_current at the new folder and have the service reload on a signal or when a version file changes. Never rebuild in place under a running service; load_index reads several files and a half-written folder produces inconsistent ids between entities and embeddings.

My corpus is private. Can I still use a hosted model for the judge?

The judge sees questions and answers, which contain your corpus's content, so the same data policy applies as for generation. If hosted models are not allowed, use a local model through get_llm("ollama") for both, pick the strongest local model you can run as the judge, and calibrate it against your own labels, since smaller judges are noisier.

Key takeaways

  • Keep the service thin: minigraphrag's search functions do retrieval; your code routes, cites, streams and measures.
  • One answer() function used by the API, the evaluator and the cost report guarantees their numbers agree.
  • Citations must resolve to documents and spans, and unresolved markers are a measurable hallucination signal.
  • Evaluate by question type with order-swapped pairwise judging, intervals and a separate judge; context recall flatters global search.
  • Meter inside the cache and attribute tokens to stages; gleaning and claims are often the largest avoidable indexing costs.
  • An honest report that the graph does not help on your corpus, with numbers, is a successful capstone.
