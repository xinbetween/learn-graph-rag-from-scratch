一张图看懂 GraphRAG

检索增强生成（retrieval-augmented generation，RAG）回答问题分两步：先从你自己的数据中检索相关材料，再让大语言模型（LLM）依据这些材料作答并给出引用。经典 RAG 检索的是嵌入（embedding）与问题相近的文本分块（chunk）。这种做法擅长查找型问题（“2024 年 Kestrel 的声呐由谁供货？”），但遇到证据分散在各处的问题（“Kestrel 为什么启动 Project Tern？”），或需要纵览整个文档集的问题（“这些文档的主要主题是什么？”），效果就很差。

GraphRAG 指的是一类在文档和模型之间加入一张图的方法。建索引时，LLM 通读文档，抽取（extraction）出实体（人物、组织、项目）以及它们之间的关系。随后合并重复的名称，把图划分成由紧密相连的实体组成的社区，并为每个社区撰写一份摘要。查询时，检索器会利用这种结构：要么从问题中提到的实体出发沿边展开，要么读取社区摘要来回答关于整个语料的问题。最后，LLM 依据检索到的实体、关系、摘要和原文写出答案。

放到 Kestrel Labs 上看：有了这张图，检索器在回答“Kestrel 为什么启动 Project Tern？”时，可以从 Project Tern 出发，走到 Deepcast（Tern 要替代的正是它的声呐），再走到 Marlow Dynamics（它收购了 Deepcast），一路收集到解释这一决定的三条事实。而纯向量检索呢？你会在第 3 章亲自测到：对这个问题，报道那次收购的文章在 24 个分块中只排第 21 位。

GraphRAG 是一类方法

“GraphRAG”也是 Microsoft Research 一篇论文及其开源项目的名字，正是它在 2024 年让这类方法流行起来。本课程用这个词泛指整个方法家族：Microsoft 式的社区摘要、LightRAG 的关键词级检索、HippoRAG 的个性化 PageRank、基于路径和子图的检索、在现有知识图谱上做 Text2Cypher，以及智能体式图搜索。每一种你都会亲手实现一个小版本。

简史

不了解这段历史并不妨碍你动手构建，但它能解释这个领域为何是今天的样子，以及为什么这么多方法的名字如此相似。

时间里程碑与本课程的关系
2020Lewis 等人提出检索增强生成这一名称：一个稠密检索器加一个生成器。同年还出现了 REALM 和 Dense Passage Retrieval。每一章都在用的“先检索、后生成”循环（第 1 章）。
2022–2023对话模型让 RAG 成为基于私有数据问答的默认做法：分块、嵌入、向量检索、写提示词。IRCoT、ReAct 等迭代式方法把检索和推理交替进行。Think-on-Graph（2023）让 LLM 一步步探索知识图谱。向量基线（第 2 章）及其在多跳问题上的局限（第 3 章）。
2024 年初RAPTOR 在分块之上递归地构建摘要树。G-Retriever 为图问答检索子图。Microsoft Research 介绍 GraphRAG 并发表 From Local to Global：由 LLM 抽取的实体图、社区报告，以及 map-reduce 式的全局搜索。社区发现与社区报告（第 11、12、15 章），子图检索（第 19 章）。
2024 年中至年底Microsoft 开源 GraphRAG。HippoRAG 在实体图上用个性化 PageRank 为段落排序。LightRAG 提出支持增量更新的双层关键词检索。第一批 GraphRAG 综述问世。Microsoft Research 发布 LazyGraphRAG，以降低索引成本。PPR（第 17 章）、LightRAG（第 16 章）、成本（第 26 章）。
2025又一篇综述把这个领域划分为知识组织、知识检索和知识融合三部分。HippoRAG 2 和 PathRAG 改进了图检索。Graph-R1 用强化学习训练智能体式图检索器，GraphSearch 提出在图上进行智能体式深度搜索的工作流。面向智能体的时序图记忆（Zep、Graphiti）投入生产使用。路径与智能体（第 18、30 章）、结合图训练模型（第 24 章）、时序图（第 27 章）。
2026Microsoft GraphRAG 进入维护模式，而它的思想已扩散到众多框架中。研究重点转向成本（例如 LiteRAG）、构建在普通数据库之上的双时态图引擎（post-graph-rag），以及在真实领域中细致比较混合 GraphRAG 何时胜过经典 RAG。框架、生产实践与研究地图（第 28、29、33 章）。

这段历史中贯穿着两条主线。一条是构建更好的索引（图、树、社区），让检索有更多可用的材料；另一条是构建更好的检索器（PageRank、路径、智能体），在查询时利用结构。如今大多数系统两者兼用，再加上普通的向量检索和关键词检索。

本课程采用的分类框架

GraphRAG 论文每月动辄几十篇，你需要一张地图。本课程采用 Zhang 等人的综述 A Survey of Graph Retrieval-Augmented Generation for Customized Large Language Models 中的三阶段结构，以及按这一结构整理的 DEEP-PolyU/Awesome-GraphRAG 论文清单。每种方法都要回答三个问题：知识如何组织成图？如何检索？又如何融入模型的生成过程？

读到一篇新论文时，先把它放到这张地图上。以 LightRAG 为例：它主要是一种组织方式上的选择（带关键词描述的实体和关系），再加上一个基于相似度的双层检索器。Think-on-Graph 则是在现有知识图谱上运行的、基于 LLM 的多轮检索器。第 33 章会带着你一路读过的论文回到这张地图。

认识 Kestrel Labs

课程中的每个示例、练习和项目都使用同一个虚构世界，这样你可以看着同一张图从原始文本长成社区，再到回答问题。正因为它是虚构的，没有任何语言模型了解它：当模型答对一个关于 Kestrel 的问题时，功劳在你的检索。

Kestrel Labs 是位于沿海城市 Port Avalon 的一家海洋科技初创公司，2021 年由 Dr. Mira Okafor（CEO，曾是 Tidewater Institute 的研究员）和 Jonas Vehl（任 CTO 至 2026 年 3 月，之后任首席科学家）共同创立，主要研发自主水下无人机。公司的珊瑚礁监测项目 Project Sentinel 以 Tidewater Institute 为研究合作方；2024 年 8 月，它的无人机先于潜水员发现了 Halden Reef 的大规模白化事件。Kestrel 的声呐原本全部采购自 Deepcast，直到 2025 年 4 月竞争对手 Marlow Dynamics 收购了 Deepcast 并停止对外供货。Kestrel 的应对是启动 Project Tern，自研声呐模块，由 Vehl 和 Priya Nair 共同负责；Priya Nair 此前是 Marlow 的工程师，2026 年 3 月出任 CTO。Brightwater Capital 领投了 Kestrel 的 A 轮（1200 万美元，2022 年）和 B 轮（4000 万美元，2025 年），其合伙人 Lena Park 是 Kestrel 的董事会成员。地区性法规 Ocean Health Act（2025 年）要求每季度开展珊瑚礁监测，Port Avalon City Council 因此于 2025 年 11 月与 Kestrel 签约。

搭建参考代码

minigraphrag 是专为本课程编写的一个小巧易读的 GraphRAG 实现，涵盖分块、带补漏抽取（gleaning）的抽取、实体消解（entity resolution）、社区、社区报告、八种检索方法、Text2Cypher、双时态图以及评估。各章展示的都是它的真实代码。默认情况下它只依赖 networkx 和 numpy，可以完全离线运行。

安装

你需要 Python 3.10 或更高版本。在仓库根目录下执行：

cd code
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest -q

-e 以可编辑模式安装这个包，你对 minigraphrag/ 的修改无需重新安装即可生效；有好几道练习需要你改动它。[dev] 会额外安装 pytest。整套测试应当远不到一秒就能跑完。

离线构建索引

# 模拟 LLM + 哈希嵌入器：无需联网，无需 API key，大约一秒
python -m minigraphrag index --input data/corpus --output .index

# 用不同的检索方法提问
python -m minigraphrag query --method basic  "Who supplied Kestrel's sonar in 2024?"
python -m minigraphrag query --method local  "Why did Kestrel Labs start Project Tern?"
python -m minigraphrag query --method global "What are the main themes in this corpus?"
python -m minigraphrag query --method hybrid --show-context "Who supplied Kestrel's sonar in 2024?"

建索引时每个阶段输出一行。在 Kestrel 语料上使用默认设置，你应当看到：

extracted 194 entity mentions, 154 relationship mentions
graph: 17 entities, 54 relationships
4 communities, 4 reports

索引目录里都是可以直接用编辑器打开的普通文件：text_units.json、entities.json、relationships.json、graph.graphml（可用 Gephi 或 yEd 打开）、communities.json、community_reports.json、claims.json、成对的 *_embeddings.npz/.json 文件，以及 config.json。

模拟 LLM 只是教学工具

MockLLM 通过标记短语识别课程中的每个提示词，并用确定性的启发式规则作答：抽取时查一张小型的 Kestrel 实体词表（gazetteer），关系靠共现判断，回答则是抽取式的，直接返回上下文中的句子并附上 [Data: ...] 引用。它能让你以可复现、零成本的方式看到每个检索器往上下文里放了什么。要评判一种方法实际答得好不好，请切换到真实的 LLM。

--llm 参数用于选择模型服务，具体配置通过环境变量完成。

--cache-dir 会用 CachedLLM 包装 LLM。这是一个磁盘缓存，键是模型、系统提示词、提示词和 JSON 标志四者的哈希，因此改完代码重新建索引时，完全相同的调用不会再付一次费。vLLM、LM Studio 以及其他兼容 OpenAI 的服务都可以通过 OPENAI_BASE_URL 接入。如果想用神经网络嵌入，传入 --embedder openai，或者在安装 st 扩展后传入 --embedder st:all-MiniLM-L6-v2；嵌入器名称会保存在 config.json 中，查询时自动沿用。

用 Python 做同样的事

大多数练习直接使用 Python API：

from minigraphrag import HashingEmbedder, IndexConfig, build_index, load_index
from minigraphrag.llm import get_llm
from minigraphrag.search.basic import basic_search
from minigraphrag.search.local import local_search

llm = get_llm("mock")                        # 也可以是 "openai"、"anthropic" 或 "ollama"，通过环境变量配置
build_index("data/corpus", ".index", llm, HashingEmbedder(), IndexConfig(max_gleanings=1), log=print)

index = load_index(".index")
print(index.graph.number_of_nodes(), "entities,", index.graph.number_of_edges(), "relationships")

for search in (basic_search, local_search):
    result = search(index, "Why did Kestrel Labs start Project Tern?", llm)
    print(result.method, result.llm_calls, result.sources)
    print(result.answer[:300], "\n")

每种检索方法都返回一个 SearchResult，其中包括 answer（答案）、method（方法名）、context_text（模型看到的上下文）、结构化的 context_data、sources（进入上下文的文档 id）以及 llm_calls（LLM 调用次数）。比较不同方法的 sources，是了解检索器找到了什么的最快途径。

统计调用次数：抽取时每个文本单元调用一次 LLM；每个文本单元在每轮补漏抽取中再调用一次“继续抽取”（max_gleanings=1 时不会再追问“还有遗漏吗？”，因为追问的结果也不会被使用）；每个文本单元为声明（claim）调用一次；每条需要汇总的合并描述调用一次；每份社区报告调用一次。24 个文本单元意味着，在描述摘要和社区报告之前就至少有 24 × 3 = 72 次调用。离线的模拟运行总共调用了 122 次。对于真实模型的运行，.cache/llm 中的文件数就是不同调用的确切次数：每次调用对应一个文件。

检验理解

GraphRAG 与经典向量 RAG 的区别是什么？

  1. GraphRAG 在查询时不使用 LLM
  2. GraphRAG 会为实体、关系（通常还有社区摘要）建立索引，检索时利用这种结构
  3. GraphRAG 只能搭配 Neo4j 这类图数据库使用
  4. GraphRAG 完全取代了嵌入
循环依然是“先检索、后生成”。变化在于索引了什么，以及检索如何在其中导航。大多数 GraphRAG 系统仍然使用嵌入，例如用来查找种子实体。

在综述的分类框架中，基于实体图的个性化 PageRank 检索（HippoRAG）属于哪个阶段？

  1. 知识组织
  2. 知识融合
  3. 知识检索
  4. 评估
PPR 是在已有的图中寻找证据的一种方法。图如何构建属于组织；证据如何进入模型的回答属于融合。

为什么 Kestrel Labs 语料是虚构的？

  1. 真实文档太长，无法建索引
  2. 许可限制不允许使用真实的新闻报道
  3. 图算法只适用于合成数据
  4. 没有任何模型具备关于它的参数化知识，所以正确答案只能来自检索
如果用真实公司，模型可能凭记忆作答，从而掩盖检索的失败。虚构世界让每一次成功和失败都能归因。

典型问题 6“Kestrel Labs 的 CTO 是谁？”被归为时间类。即使图是完美的，它难在哪里？

  1. 语料中从未提到 CTO 的名字
  2. 先后有两个人担任过这一职位，图需要记录有效期才能返回现任者
  3. CTO 是一个无法消解的别名
  4. 它需要对整个语料做全局归纳
Jonas Vehl 担任 CTO 至 2026 年 3 月，此后由 Priya Nair 担任。边上如果没有时间信息，两个人都会是“CTO”。

你在没有 --llm 参数、也没有任何 API key 的情况下运行 python -m minigraphrag index，会发生什么？

  1. 报错并要求提供 OPENAI_API_KEY
  2. 下载一个小型本地模型
  3. 使用 MockLLM 和 HashingEmbedder 离线运行，大约一秒生成一个确定性的索引
  4. 跳过抽取，只构建向量索引
模拟 LLM 是默认选项，这样整门课程都能离线运行，也能在 CI 中运行。要获得真实的回答，请使用 --llm openai|anthropic|ollama。

--cache-dir .cache/llm 的作用是什么？

  1. 存放索引产物
  2. 缓存嵌入以加快搜索
  3. 为评估框架保存查询答案
  4. 用 CachedLLM 包装 LLM，完全相同的调用（模型、系统提示词、提示词、JSON 标志都相同）直接从磁盘读取，不必再次付费
建索引会产生大量调用。确定性的提示词加上以哈希为键的缓存，让改代码后的重跑成本很低。

常见问题

开始学习之前，需要懂图论或机器学习吗？

不需要。你只需熟悉 Python，能看懂简短的公式。第 4 章会从零讲解你需要的图论知识（邻接、遍历、最短路径、PageRank、模块度），第 2 章讲解嵌入。只有讲结合图训练模型的第 24 章默认你对模型训练有一定了解，而且除完整路径外，它在其他路径上都是选修。

为什么要从零构建，而不直接用 Microsoft GraphRAG、LightRAG 或 LlamaIndex？

因为只会配置、不懂原理，到了生产环境就会出问题：如果整条流程是个黑盒，你就没法调优抽取提示词、选择社区层级，也没法解释一个糟糕的答案从何而来。这些框架都很好，第 28 章会专门讲。亲手构建过 minigraphrag 之后，你再读它们的配置文件和源代码，看到的将是你已经写过的东西的各种变体。

用真实 LLM 做练习要花多少钱？

对 Kestrel 语料来说非常少：建索引要对大约 5,400 个英文单词的原文进行约 120 次 LLM 调用（使用模拟 LLM 和默认设置时为 122 次），一次查询则视方法不同需要一次到几十次调用。用小型托管模型的话，整门课程下来通常只需几美分到几美元，而且有了 --cache-dir，每个不同的调用只付一次钱。通过 Ollama 使用本地模型不花钱，只花时间。第 26 章会针对成本真正要紧的大规模语料算这笔账。

模拟 LLM 的答案看起来像是照抄的句子，是哪里出问题了吗？

没有。模拟 LLM 是刻意采用抽取式回答的：它返回上下文中与问题最匹配的句子，每句都带 [Data: ...] 引用。这让它成了一扇窗口，透过它可以看到检索器找到了什么。只要正确的句子出现了，就说明检索成功；把它们写成一个通顺的答案，是真实模型的工作。

可以用我自己的文档代替 Kestrel 吗？

可以：--input 接受任何包含 .md 文件的文件夹。不过请先用 Kestrel 学完各章，因为练习和解答都以它为准，之后再在你自己的数据上重跑感兴趣的练习。那时你需要真实的 LLM，因为模拟 LLM 的实体词表只认识 Kestrel 中的名字。

  • GraphRAG 保留了“先检索、后生成”的循环，并在文档和模型之间加入一张由实体、关系和社区摘要构成的图。
  • 这个领域从 RAG（2020）起步，经过 Microsoft 的 GraphRAG、HippoRAG 和 LightRAG（2024），发展到智能体式和时序图检索（2025–2026）。
